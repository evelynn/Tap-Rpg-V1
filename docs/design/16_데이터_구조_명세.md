# 16 데이터 구조 명세

버전 0.2 · 작성일 2026년 9월 22일 · 상위 문서 00_문서지도.md, 01_핵심규칙_수치기준.md

게임을 이루는 데이터를 **정적 데이터**(콘텐츠 정의: 장소, 적, 장비, 특성, 사건 등)와 **동적 데이터**(저장: 가문, 인물, 가방, 일지, 진행 상태)로 나누어 구조를 정한다. 엔진에 의존하지 않도록 JSON으로 정의하며(00 O05), 규칙 구현자와 콘텐츠 작성자가 같은 필드 이름으로 이야기할 수 있게 하는 것이 목적이다. 수치의 출처는 01이고, 각 콘텐츠의 세부 값은 담당 문서가 정한다. 이 문서의 JSON 예시에 들어간 콘텐츠 값은 **구조 설명용**이며, 원문과 수치는 담당 문서가 확정한다.

**이 문서가 소유하는 규칙(00 §2.4)**: 데이터 형식, 효과·조건 문법, **템플릿 변수 등록표**(1.4절), **플래그 키 등록표**(5.2절). 판정 종류의 이름과 조합은 05 §6.1, 자동 선택 모델(태그·위험 등급·점수식)은 10 §5, 소모품 필드 값은 08 §4.2가 소유하며 이 문서는 그것을 데이터 키로 옮긴다.

관련 문서: 01(수치·ID·공유 명칭), 04(행동 상태·목적지 고정), 05(판정 종류), 06(특성), 07(적·장소·재료), 08(장비·소모품·교체 제안), 09(생애·흡혈귀), 10(사건 시스템·자동 선택), 11(사건 원문), 12(계승·후손 반응), 13(저장 절차), 14(일지 문장·조사 규칙), 15(스프라이트 ID)

### 1.2 명명과 기본 타입

- 필드 이름은 `snake_case` 영어다. 열거값도 영어 소문자 `snake_case`다(6절 열거형 목록).
- 사람이 읽는 이름과 문장은 한국어 문자열을 그대로 넣는다. 첫 검증판은 다국어를 지원하지 않는다.
- 공통 타입:

| 타입 | 형식 | 예 |
| --- | --- | --- |
| `id` | 문자열. 00 §2.2 접두사 규칙 | `"W07"`, `"C01-3"`, `"D2"` |
| `uid` | 동적 개체의 고유 식별자. `"{접두}_{가문 내 일련번호}"` | `"it_000412"`, `"ch_0002"` |
| `flag_key` | `범위.snake_case`. 범위는 `life`·`fam`·`trip`(00 §2.2). 5.2절 등록표의 키만 쓴다 | `"fam.c01_rescue"` |
| `int` | 정수 | `12` |
| `ratio` | 0~1 실수. 비율·확률 | `0.3` |
| `pct_point` | 정수 퍼센트포인트. 퇴각 기준 가산 등 | `10` |
| `range` | `[최소, 최대]` 정수 배열, 양 끝 포함 | `[8, 16]` |
| `eff_min` | 유효 진행 분(실수, 소수 둘째 자리) | `213.75` |
| `utc_ms` | UTC 밀리초 정수 | `1790000000000` |
| `template` | 1.4절 문장 템플릿 문자열 | `"{name:이/가} 다리를 건넜다."` |
| `condition` | 3절 조건 표현식 | `{"age_gte": 35}` |

### 1.3 ID 참조 규칙

- 정적 데이터는 서로를 **ID로만** 참조한다. 이름 문자열로 참조하지 않는다.
- 동적 데이터는 정적 정의를 ID로(`def_id`), 동적 개체를 `uid`로 참조한다.
- 방어구 `A01`(두 자리)과 모험 경로 `A1`(한 자리)은 자릿수로 구분한다(00 §2.2). 로더는 참조 필드의 기대 종류(장비/장소)로도 검사한다.
- 연속 사건은 줄기 ID(`C01`)와 단계 ID(`C01-3`)를 구분한다. 장신구는 `J` 접두사(J01~J05, D17)를 쓰므로 연속 사건 줄기 `C01`·`C02`와 문자열이 겹치지 않는다. 로더는 참조 필드의 기대 종류(`item_id` 대 `chain_id`)로도 검사한다.
- 스프라이트 부품 ID는 15가 정한다(머리 `HR01~HR06`, 외형 계열 `V`, 효과 `FX`). 장소 접두 `H`와 겹치지 않는다(00 §2.2).
- 플래그는 항상 범위 접두를 포함한 전체 키로 저장·참조한다(`"fam.c01_rescue"`, `"c01_rescue"` 아님).

### 1.4 문장 템플릿 문법

이 절이 문법과 **변수 등록표**의 기준이다(00 §2.4). 문형과 사용 규칙은 14, 조사 판정 규칙은 14 §6이 정하고 이 문서는 그것을 구현한다.

#### 1.4.1 문법

- 변수: `{변수}`. 조사 붙이기: `{변수:받침형/무받침형}`. 예: `{name:이/가} {item:을/를} 내려놓았다.`
- 중괄호 문자를 그대로 쓰려면 `{{`, `}}`로 적는다.
- 변수 안에서 계산식을 쓰지 않는다(`{luck-2}` 불가). 계산 결과가 필요하면 별도 변수를 등록한다(`{luck_after}`).
- 등록표(1.4.3)에 없는 변수는 콘텐츠 검사 V5 오류다. 1.4.4 옛 표기는 경고와 함께 정식 이름으로 바꿔 읽는다.

#### 1.4.2 조사

| 표기 | 받침 있음 | 받침 없음 | ㄹ 받침 | 병기형(판정 불가) |
| --- | --- | --- | --- | --- |
| `{x:이/가}` | 이 | 가 | 이 | `이(가)` |
| `{x:은/는}` | 은 | 는 | 은 | `은(는)` |
| `{x:을/를}` | 을 | 를 | 을 | `을(를)` |
| `{x:과/와}` | 과 | 와 | 과 | `과(와)` |
| `{x:으로/로}` | 으로 | 로 | **로** | `(으)로` |
| `{x:아/야}` | 아 | 야 | 아 | `아(야)` |
| `{x:이랑/랑}` | 이랑 | 랑 | 이랑 | `(이)랑` |
| `{x:이나/나}` | 이나 | 나 | 이나 | `(이)나` |
| `{x:이라/라}` | 이라 | 라 | 이라 | `(이)라` |

**받침 판정은 14 §6을 그대로 구현한다.**

1. 판정 대상은 치환된 값의 마지막 글자다. 끝의 공백·닫는 괄호·따옴표·문장부호는 건너뛴다.
2. 한글 음절(가~힣): 종성 번호 = (문자 코드 − 0xAC00) mod 28. 0이면 받침 없음, 8이면 ㄹ 받침, 그 밖은 받침 있음.
3. 숫자: 끝자리 1·7·8은 ㄹ 받침, 3·6은 받침 있음, 2·4·5·9는 받침 없음, 0은 받침 있음(십·백·천·만, 단독 0은 영).
4. 영문: 끝 글자가 a·e·i·o·u·y·w·r이면 받침 없음, l이면 ㄹ 받침, m·n이면 받침 있음. 그 밖의 자음과 판정할 수 없는 문자(한자·기호·이모지)는 **병기형**.
5. `으로/로`: 받침 없음 또는 ㄹ 받침이면 `로`, 그 밖의 받침이면 `으로`.

## 3 조건과 수정자

### 3.1 조건 표현식 문법

조건은 JSON 객체다. 결합자와 단말(leaf)로 이루어진다.

| 형태 | 뜻 | 예 |
| --- | --- | --- |
| `{"all": [c1, c2, ...]}` | 모두 참 | `{"all":[{"age_gte":35},{"age_lt":65}]}` |
| `{"any": [c1, c2, ...]}` | 하나 이상 참 | `{"any":[{"attitude":["adventurous","challenging"]}]}` |
| `{"not": c}` | 부정 | `{"not":{"mutation":"vampire"}}` |
| `{단말키: 값}` | 단말 조건 | `{"season":["winter"]}` |
| `{"num": {"key", "op", "value"}}` | 일반 수치 비교. `op`: `==` `!=` `>=` `>` `<=` `<` | `{"num":{"key":"stat.soc","op":">=","value":3}}` |
| `true` / `false` | 상수 | `true` |

- 빈 `all`은 참, 빈 `any`는 거짓이다.
- 단말 객체에 키가 둘 이상이면 로드 오류다. 여러 조건은 `all`로 묶는다.
- 조건 평가는 부수 효과가 없고 **난수를 쓰지 않는다**. 확률 분기는 효과 `chance`(4.3절)가 담당한다.

| 필드 | 형식 | 필수 | 설명 |
| --- | --- | --- | --- |
| `id` | string | O | 사건 안에서 고유 |
| `label` | string | O | 선택지 문구 |
| `short` | string | hold=none O | 과거형 요약. 이유 문장의 `{choice_short}`(10 §5.6) |
| `tags` | enum[] | hold=none O | 성격 태그 1~2개: `safe` `thrift` `rest` `kindness` `info` `new_path` `reward` `bold`(10 §5.1) |
| `risk` | enum | O | 선택지 위험: `none` `low` `medium` `high` `lethal`(10 §5.4). 실패 시 가장 나쁜 결과로 정한다 |
| `requires` | condition | - | 이 선택지가 보이는 조건 |
| `check` | check | - | 판정. `combat`과 함께 쓰지 않는다 |
| `combat` | combat | - | 선택지 자체가 전투일 때 |
| `decline` | bool | - | 안전한 종료 선택지. `새로운 운명 제안은 거절하고 계속` 방침이 고른다(F01 `아직은`, F02 `그대로 돌아선다`, F03 `잔을 내려놓는다`) |
| `preview` | object | hold≠none O | 선택 창 칸 `{benefit, cost, reversible}`(10 §8.3). 판정이 있으면 창이 능력치·숙련·난이도·성공 확률을 덧붙인다 |
| `outcomes` | object | O | 키: `crit_success` / `success` / `partial` / `failure` / `crit_failure` / `always` / `win` / `defeat` / `stalemate` |

- 자동 선택 점수는 저장하지 않는다. 엔진이 `tags`·`risk`·판정 성공 확률과 태도(2.2절 `tag_scores`), 특성(`choice_tag_bonus`)으로 매번 계산한다(**10 §5 참조**). 11의 `안·모·도` 열은 표준 조건 계산 결과를 적어 둔 것이며 데이터에 넣지 않는다.
- 사건마다 `risk`가 `none` 또는 `low`인 선택지가 최소 하나 있어야 한다(V7).

**check** (판정 종류의 능력치·숙련·부분 성공 기본값은 05 §6.1 → 6.13절 `check_kinds`에서 읽는다. 사건이 조합을 새로 만들지 않는다)

| 필드 | 형식 | 설명 | 예 |
| --- | --- | --- | --- |
| `kind` | enum | 판정 종류 키(6.13절). `any_of`와 둘 중 하나 | `"force"` |
| `any_of` | enum[2] | **선택형 판정**(05 §6.1): 보정 합이 높은 쪽으로 한 번 굴린다. 같으면 앞의 것 | `["lore","persuade"]` |
| `dc` | int | 고정 DC. `dc_offset`과 둘 중 하나 | `16` |
| `dc_offset` | int | 지역 기준 DC(01 §3.2) + 값. 마을 사건은 인물 레벨 기준 | `2` |
| `partial_allowed` | bool | 종류 기본값을 **끄는** 용도로만 쓴다. 기본값이 불가인 종류를 켤 수 없다(`attack_event`는 사건이 정함) | `false` |
| `situational` | modifier[] | 이 판정에만 붙는 상황 보정(`when` 가능) | `[{"target":"check.all","op":"add","value":2,"when":{"flag":"life.c01_map_read"}}]` |

`crit_success`·`crit_failure`가 없으면 각각 `success`·`failure`를 쓴다(대성공 보상 +50%는 05 §6.4). `partial`이 없으면 부분 성공 구간은 실패로 처리한다.

**combat**

| 필드 | 형식 | 설명 | 예 |
| --- | --- | --- | --- |
| `enemies` | object[] | `{enemy_id}` 또는 `{by_location: {장소 ID: 적 ID}}` | `[{"by_location":{"H2":"EN03","A2":"EN03","H3":"EN04"}}]` |
| `count` | int 또는 `[{when, count}]` | 적 수. 조건별 수 | `[{"when":{"level_lt":8},"count":1},{"when":true,"count":2}]` |
| `sequential` | bool | 여러 적을 한 체씩 연속으로 | `true` |
| `first_strike` | enum | `char` / `enemy` / `default`(01 §4) | `"char"` |
| `pre_check` | object | 전투 전 판정 `{kind, dc_offset, on_fail: modifier[]}` — 실패 효과는 이 전투에만 | `{"kind":"fear","dc_offset":0,"on_fail":[{"target":"hit","op":"add","value":-2}]}` |
| `reward_mult` | number | 적 동전·경험치 배수 | `1.5` |

전투 결과 키는 `win` / `defeat` / `stalemate`다. `defeat`는 효과를 적지 않아도 01 §6.3 일반 패배 처리가 적용된다(치명 활동이 아니므로 사망 없음).

**outcome**

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `effects` | effect[] | 4.3절 효과. 순서대로 적용 |
| `line` | template | 한 줄 기록(≤28자, 과거형, 14) |
| `detail` | template | 상세 기록 |
| `tag` | enum | 기록 태그(6.9절). 없으면 사건 `intro.tag` |

### 4.3 효과 종류 (50종)

모든 효과는 선택 필드 `when`(condition)을 가질 수 있다. 조건이 거짓이면 그 효과만 건너뛴다.

**자원·상태**

| type | 파라미터 | 설명 |
| --- | --- | --- |
| `add_coins` | `amount` \| `units` \| `formula` | 동전 획득. `units`는 10 §6 동전 단위 × 값 |
| `remove_coins` | `amount` \| `units` \| `ratio` | 동전 잃음. 0 아래로 내려가지 않음 |
| `add_xp` | `amount` \| `units` \| `encounters` | 경험치. `units`는 경험치 단위 × 값 |
| `heal` | `hp` \| `hp_ratio` | 체력 회복 |
| `damage` | `hp` \| `hp_ratio` \| `dice` | 체력 감소. 사건 피해는 체력 1 아래로 내리지 않음(V9) |
| `add_fatigue` | `value`(음수 가능) | 피로 |
| `injury` | `grade`(`light`/`serious`), `stat`(선택) | 부상. 경상 상한(01 §6.2) 적용 |

| `life_stat_add` | `stat`, `value`, `floor`(기본 0) | 이번 생애 동안의 능력치 변화(F02 대체 대가 행운 −2) |

| --- | --- | --- |

### 5.2 플래그 키 등록표

**이 표가 플래그 키의 유일한 등록표다**(00 §2.4). 문서와 데이터는 이 표의 키만 쓴다. 새 키는 여기 먼저 등록한다.

- 형식: `범위.snake_case`. `{place}`·`{kind}`·`{role}`이 붙은 키는 뒤에 장소 ID·종류 키를 이어 붙인 **키 묶음**이다(예: `life.l01_marked_H1`).
- 저장 위치: `fam.` → `family.flags`, `life.` → `character.flags`, `trip.` → `current_activity.sortie.trip_flags`. 모두 전체 키 그대로 저장한다.
- 수명: `fam.`는 영구 보존(반응 기간이 끝나도 지우지 않음, 12 §7.6), `life.`는 생애 종료 시 연대기로 옮기고 지움, `trip.`는 출정 종료 시 지움.

- 이동 중에는 사건을 검사하지 않는다(10 §3.1 이동 0%). 따라서 `travel` 판단 지점은 없다. 모험의 다른 장면(발견·길 선택·채집·조우)도 사건을 검사하지 않는다.
- 나이 이정표 사건(L23)은 `town_return` + `specific_age` 조건으로 만든다.

## 7 검증 규칙

### 7.1 저장 파일 로드 시 검사

**치명 검사** — 하나라도 실패하면 손상으로 판정하고 13 §8.5 복구 절차로 넘어간다.

| 번호 | 검사 |
| --- | --- |
| K1 | JSON 해석 가능, `header`·`body` 존재 |
| K2 | 체크섬 일치 |
| K3 | `schema_version`이 정수이고 이전 함수가 존재 |
| K4 | 5절 필수 필드 존재, 형식 일치 |
| K5 | 모든 `def_id`·장소·사건·특성 ID가 정적 데이터에 존재(삭제된 ID는 이전 함수가 대체해야 함) |
| K6 | `inventory`의 모든 uid가 `item_instances`에 존재 |
| K7 | `state` 열거값 유효, `pending_choice`가 있으면 `state = awaiting_choice` |

**보정 검사** — 실패하면 아래 방식으로 고치고 진단 로그에 남긴 뒤 계속한다.

| 번호 | 검사 | 보정 |
| --- | --- | --- |
| B1 | 능력치 원값 0~8. 예외: TA08 보유 시 의지 9(01 §11), 흡혈귀 힘·민첩 9(09 §7.2). 판정 보정 포함 값 0~10 | 범위로 자름 |
| B2 | 레벨 1~30, xp가 다음 레벨 요구량 미만 | 넘치면 레벨업 처리 |

| B5 | 장착 슬롯과 장비 슬롯 일치 | 불일치 장비를 가방으로 |
| B6 | 유품 지정 ≤ 2, uid 중복 없음, priority 1·2 | 뒤쪽 지정 해제 |
