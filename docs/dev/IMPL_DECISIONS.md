# 구현 결정 기록 (I-번호)

설계 문서(docs/design)에 없거나 모호한 **구현 세부**를 코드에 옮기면서 정한 결정이다. 게임 규칙 자체를 바꾸는 결정은 여기서 끝내지 않는다. 먼저 해당 소유 문서(00 §2.4)를 고치고, 00 §3에 D-번호로 기록한다. 여기에는 규칙을 바꾸지 않는 구현 선택만 적는다.

| ID | 결정 | 이유 | 관련 |
| --- | --- | --- | --- |
| I01 | 테스트 러너는 Node 내장 `node:test` + `node:assert/strict`, TypeScript 실행은 `tsx`를 쓴다 | 개발 환경에서 npm 레지스트리 접근이 막혀(403) 로컬 pnpm 저장소에 있는 패키지만 설치할 수 있다. vitest 메타데이터가 캐시에 없다. 내장 러너로도 단위·결정성 테스트에 충분하다 | T1 |
| I02 | `pnpm.overrides`로 esbuild를 0.25.9에 고정하고, tsx 4.19.3을 쓴다. 설치는 `pnpm install --offline`으로 한다 | 캐시에 있는 esbuild가 0.25.9뿐이다. 네트워크가 열리면 최신 버전으로 올려도 된다 | T1 |
| I03 | 코어(`packages/core/src`)는 `types: []`로 타입 검사해 Node·DOM API 사용을 컴파일 단계에서 막는다. 테스트는 `tsconfig.test.json`으로 따로 검사한다 | 코어를 Tauri 웹뷰(M2)와 Node 시뮬레이터가 함께 쓰기 위해서다 | T1 |
| I04 | 코어 소스의 문자열 리터럴에 콘텐츠 ID(H1, L01, EB03 …)가 있으면 `pnpm lint:ids`가 실패한다. 꼭 필요하면 그 줄에 `id-lint-allow`를 붙인다 | 규칙이 콘텐츠 ID가 아니라 데이터 속성을 보게 해, 코어 수정 없이 콘텐츠를 늘리기 위해서다 | T1 |
| I05 | 난수는 PCG32(XSH RR, 64비트 상태·증분)를 BigInt로 계산한다. 흐름 시드는 13 §8.3대로 `SHA-256(UTF-8(family_seed + ":" + 흐름))`의 앞 16바이트이며, 앞 8바이트를 initstate, 뒤 8바이트를 initseq(빅엔디언)로 `pcg32_srandom`에 넣는다. `family_seed`는 소문자로 바꾸지 않고 그대로 해시한다. 상태는 `{state, inc}` 16자리 소문자 16진으로 쓰고, 읽을 때는 대소문자를 받되 inc는 홀수만 받는다. SHA-256·UTF-8 인코딩은 코어에 순수 TS로 둔다 | 코어는 `types: []`라 node:crypto·TextEncoder를 쓸 수 없다. 기준 벡터 pcg32_srandom(42, 54)와 node:crypto 대조 테스트로 검증한다. 저장 스키마(T11)는 family_seed가 16자리 소문자 16진임을 보장해야 한다. 시뮬레이터 속도가 문제되면 u32 쌍 연산으로 바꿔도 출력은 같다 | T4a, 13 §8.3, 16 §5.8 |
| I06 | 난수 소비량은 데이터 값에 따라 달라지지 않는다. `chance(p)`는 p가 0이나 1이어도 u32 1개를 쓴다. `bounded(n)`은 1~2³²−1 정수만 받는다. `weightedIndex`는 음이 아닌 정수 가중치만 받고 합이 0이면 오류다. `pick([])`도 오류다. 오류는 모두 RangeError다 | 확률을 패치로 0이나 1로 바꿔도 같은 흐름의 뒤 결과가 밀리지 않게 하기 위해서다 | T4a |
| I07 | 난수 흐름 배정: `combat` = 전투 라운드 주사위·피해·매복·도주. `event` = 사건 발생·사건 판정·선택지 미리 굴림·`chance` 효과. `loot` = 동전 변동·드롭·등급·장비 부가 효과·상점 재고. `life` = 출생 능력치·특성·자녀 후보·유전·외형·레벨업 배분·부상 능력치 선택. `world` = 출정 시간대·날씨·던전 방 구성·길바뀜·장면·함정 종류·활동과 장소 선택·조우 적 선택·행동 시간·비전투 판정(함정 회피·험로) | 결정성을 지키려면 13 §8.3 표에 없는 용도도 흐름 하나에 고정해야 한다. 표에 없는 확장 항목(매복·도주, 장비 부가 효과, `chance`, 레벨업 배분, 부상 능력치, 장면·함정 종류, 활동·장소·조우 적 선택, 행동 시간, 비전투 판정)은 13 §8.3 표 갱신 대상이다 | T4a, 13 §8.3 |
| I08 | `@tap/core` 공개 이름: text 모듈의 변수 추출 함수는 `extractTemplateVars`로 내보낸다. `templateVars`라는 이름은 W4 템플릿 변수 등록부가 쓴다. time 모듈의 `SEASONS`·`LIFE_STAGES`는 schema/common과 값이 같으므로 common 쪽을 내보낸다 | 두 모듈을 `export *` 하면 이름이 겹친다(TS2308). CONTENT_SCHEMA가 부르는 등록부 이름을 유지하고 함수 이름을 바꿨다. time 모듈은 common의 상수를 가져다 쓴다(중복 정의를 없앴다) | T4a, W4 |
| I09 | 템플릿 조사는 14 §6을 그대로 구현한다(조사 쌍은 16 §1.4.2의 9종). 영문 m·n은 받침 있음(`Tom이`), 영문 대소문자는 가리지 않는다. 끝의 공백·닫는 괄호·따옴표·문장부호는 건너뛴다. 판정할 수 없는 끝 글자(한자·자모 단독·기호·이모지)나, 전부 건너뛰어 남는 글자가 없는 값은 병기형이다. 숫자 값은 `String()`으로 넣는다. 값이 있는지는 `Object.hasOwn`으로 본다. 파서는 중괄호 짝 불일치, 비었거나 공백이 든 변수 이름, 9종 밖 조사 쌍을 예외로 던지며 `extractTemplateVars`도 같은 파서를 쓴다 | 콘텐츠 검사 V5가 한 번 호출로 문법과 조사 쌍까지 본다. 14 §6 5항에는 병기형 6종만 적혀 있어 (이)랑·(이)나·(이)라가 빠져 있다(14 보완 후보) | T4a, 14 §6, 16 §1.4 |
| I10 | 생애 단계 경계 나이는 `balance.aging.life_stages`의 prime·veteran·elder `from_age`를 튜플로 만들어 `lifeStageAt(age, [30, 50, 65])`에 넘긴다. `stageBoundaryReached`는 나이 기준이며, 판단 지점 사이에 새로 넘은 경계 중 가장 이른 것 하나만 돌려준다. 계절 순서는 16 §6.11을 따르고, 출발 계절은 인물의 eff_min 0 시점 계절이다 | 경계 나이의 단일 출처는 `balance.aging.life_stages`다(CONTENT_SCHEMA §5.1 필드 규칙). 16 §2.1의 `balance.offline.stage_boundaries`는 이 스키마에 없다(`time/calendar.ts` 주석을 고쳤다) | T4a, 09 §1 |
| I11 | 팩 로더 CLI는 `check <팩 경로...> [--json] [--strict]`와 `schema <출력 폴더>` 두 명령이다(CONTENT_SCHEMA §9의 `validate`·`bundle --packs` 모양이 아니다). 번들 파일을 쓰는 명령은 아직 없고, 번들은 `validateContent` API로 받는다. 팩 id 중복은 P06, 팩이 없거나 pack.json이 없으면 P01, 패치로 id를 바꾸면 P07, 문자열 `id`가 없는 정의는 S01로 보고한다. 파일 앞 UTF-8 BOM은 떼어낸다. 번들 defs에는 zod 기본값을 채운 값이 아니라 패치를 적용한 원본을 담는다. JSON Schema 내보내기(`pnpm content:schema`)를 두며, 조건 필드는 `{}`로 나온다 | 과업 지시와 T2 검증 조건("JSON Schema 파일 생성")을 따랐다. CONTENT_SCHEMA §2.1·§9 W1의 CLI·API 모양과 JSON Schema 문장을 이 결정에 맞게 고쳤다 | T2 W1 |
| I12 | 종류 스키마의 해석: 선택 필드(`?`)는 생략만 허용하고, null은 문서가 `\| null`로 적은 필드만 받는다. 퍼센트 필드는 ratio다(`item_effect.value_pct` 0.03). `= 기본값` 필드는 W2가 `.default()`로 채우고, W4는 엔진 기본값을 optional로만 둔다(파싱 결과가 작성한 데이터와 같다). record 모양 balance 섹션(check_kinds·specializations·life_stage_rules)의 `_note`·`_comment`는 `noted()`로 받는다. `text.variants`는 `line[]`만 받는다. system 사건은 `weight`를 생략할 수 있다(V13 면제). `COST_REQUIRED_EFFECTS`는 효과 이름 Set이라 `remove_item` 전체가 대상이다 | 각 묶음(W2·W3·W4) 보고를 따랐다. 16 예시의 null(`base`·`shop`·`price_override`·`short_name`·`tier`·`facility`)은 기반 팩을 입력할 때 뺀다 | T2 W2·W3·W4 |
