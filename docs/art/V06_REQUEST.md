# V06_REQUEST — 이미지 생성 AI에게 넘기는 v06 요청 묶음

버전 1.0 · 2026년 9월 25일 · 받는 쪽: 이미지 생성·편집 모델을 쓰는 제작 AI(다른 터미널의 codex)
근거: V05 1차·2차 판정(`V05_REQUEST.md` 머리), 새 문 원칙(커밋 7b1f8c7, `tools/art-check/README.md` 「문 검사 (`gate`)」), 규격 고정 절차(`PROMPTS.md` §0.4), 몬스터 표준(`prompts/P2_world.md` §2.0). 이 문서는 **순서·입력·틀·합격**만 가진다. 영어 문장은 「프롬프트 위치」 칸이 가리키는 절에서 **전문 그대로** 옮긴다. 프롬프트 문서에 아직 없는 영어 문장 네 가지만 §5에 적었다.

이 묶음은 두 부분이다. **(a)** V05에서 끝나지 않았거나 보류된 것(§1, 배치 1~4 + 배치 12의 1장), **(b)** 다음 제작 물결(§2, 배치 5~34). (b)는 게임이 **첫 놀이 고리**(마을 T00 ↔ 들판 H1 한 바퀴: 주인공 기본 차림 + 들쥐·늑대·박쥐·코볼트 + 두 장소)를 가장 빨리 돌릴 수 있는 순서로 놓았다(§3).

## 0 먼저 지킬 것

### 0.1 하지 않는다

1. **코드를 쓰지 않는다.** 코드로 그림을 만들거나 고치지 않는다: 자르기·크기 바꾸기·배경 지우기·색 바꾸기·합치기·옮기기·화소 복사 모두 금지. 생성·편집 결과를 **그대로** 낸다(D56).
2. **저장소 파일을 고치지 않는다.** 쓰는 곳은 `assets/_imagegen/v06/` 하나뿐이다(그림 `.png`, 보낸 글 `.prompt.txt`, 문 출력 `.gate.txt`, 폴더 `README.md`). `tools/`, `docs/`(이 문서 포함), `docs/art/templates/`, `*.map.json`, `.gitignore`, `package.json`, 소스 코드, `assets/game/`, `assets/ready/`는 건드리지 않는다. git 스테이징·커밋도 하지 않는다(게임 쪽이 판정 뒤 한다).
3. **`tools/art-check`를 절대 고치지 않는다.** 문이 틀린 것 같으면(§0.4 예외 밖에서 눈으로 멀쩡한데 FAIL, 또는 PASS인데 눈으로 명백히 틀림) 그 자리에서 **멈추고 보고한다**(§0.5). 허용치를 바꾸거나, 다른 `--spec`·`--no-canvas`로 바꿔 돌려 통과시키지 않는다.
4. 돌려도 되는 명령은 `pnpm art:gate`(읽기만 한다) 하나다. `art:normalize`·`art:template`·`derive`·`preview`·`layers`는 게임 쪽 일이다.
5. 한 요청 = 한 장. 두 시트를 한 이미지에 담지 않고, 한 시트를 여러 장으로 나누지 않는다. 투명 배경을 요청하지 않는다(배경은 불투명 `#FF00FF`). 출력 크기를 「자동」으로 두지 않는다: 생성은 틀의 캔버스, 편집은 입력과 같은 크기.
6. 옷·무기 레이어 떼기를 요청하지 않는다(도구 `derive`가 뗀다). **「틀 필요」 시트(`PROMPTS.md` §0.4.3)는 요청하지 않는다. 예외는 두 장뿐이다**: V06-12 주인공 초상 마스터, V06-45 보스 정체성 1칸 — 둘 다 뒤 시트의 정체성 입력이라 먼저 있어야 하고, 문 없이 육안으로 본다(V05 README가 지적한 「틀 필요 금지 ↔ V05-18」 모순을 이렇게 닫는다).
7. 이 문서 「입력」 칸에 없는 이미지를 입력으로 넣지 않는다. 특히 v04 불합격본(늑대·박쥐·코볼트·걷기)과 v05 교체된 시도(`-r2`가 합격이면 원본, `-r3`가 합격이면 원본·`-r2`)를 넣지 않는다.
8. **보류** 표시 항목(V06-98)은 하지 않는다.

### 0.2 한다

- **글 조립**: 각 항목의 「프롬프트 위치」가 가리키는 조립을 그대로 쓴다. 공통 블록(A·B·T·NUM·C·D·S·S-W·X·SW·SC-*)은 줄이지 않고 전문을 붙인다. NUM은 `PROMPTS.md` §8의 해당 코드 블록 전문이다. `{…}` 자리는 그 절이 정한 값으로 바꾼다.
- **입력 순서**: 틀 항목은 입력 1 = 틀 이미지(「틀·문」 칸의 `P` = `<시트>.placeholder.png`, `G` = `<시트>.grid.png`, 모두 `docs/art/templates/`). 틀의 청록 눈금과 자리표시 인물은 결과에 남기지 않는다(T가 말한다). 편집 항목은 입력 1 = 편집할 그림이고 T·NUM을 붙이지 않는다.
- **한 계보**: 입력은 §0.7 표의 합격 원본(새 계보)만 쓴다. 한 기준 시트에서 나오는 편집·떼기는 모두 그 원본에서 만든다.
- **순서**: §3 배치 순서대로, 배치 안에서는 표 순서대로. 「선행」 칸의 항목이 합격(문 + 육안)하기 전에 시작하지 않는다.
- **편집 규칙**: 편집 결과는 입력과 같은 캔버스·칸·위치를 가진다. 결과를 입력과 겹쳐 차이가 요청한 곳에만 있어야 한다(E13·W3). 남긴 화소의 색이 입력과 같아야 한다(E21).

### 0.3 문 규칙 (2026-09-25 새 원칙, 커밋 7b1f8c7)

「틀·문」 칸에 문 명령이 있는 항목은 결과마다 `pnpm art:gate <png> --spec <시트> [칸의 옵션]`을 돌리고, 출력 전문을 `<같은 이름>.gate.txt`로 저장한다.

| 결과 | 뜻 | 할 일 |
| --- | --- | --- |
| **PASS**(종료 코드 0) | 정규화로 못 고치는 문제가 없다. `Warnings` 아래 경고가 몇 개든 통과다 | 육안 기준(「합격」 칸)으로 간다 |
| **WARN**(`Warnings (normalization fixes these; not sent to the generator)` 아래 줄) | 정규화가 고친다: 규격 키 차이, 틀 대비 위치(지면선·중심), 칸 경계 넘음, 그린 블록 크기, 배경 색 미세 차이 | **다시 만들지 않는다.** README에 경고 개수와 요점만 적는다 |
| **FAIL**(종료 코드 1) | 정규화로 못 고치는 것만: 캔버스 크기(`canvas`), 그림 수·칸 배치(`missing`·`unexpected`), 옆 그림과 닿음·겹침(`touch`), 가장자리 닿음(`edge`), 시트 안 크기 ±6%(`scale`), 한 행 안 발 높이 ±1(`ground`), 안내 색(`guide`), 배경을 열쇠로 뺄 수 없음(`background`), 격자 밖 그림(`stray`), 속 반투명(`alpha`), 띠 채움(`fill`·`ground_band`) | 먼저 §0.4 예외인지 본다. 아니면 출력의 `Regeneration feedback:` 아래 문단을 **그대로** GF 블록(`PROMPTS.md` §1)으로 같은 글 끝에 붙여 다시 만든다. 편집 항목도 같다(편집 글 끝에 GF) |

- **다시 만드는 것은 FAIL일 때뿐이다.** 한 항목의 시도는 최대 3번(처음 + 다시 2번), 파일 이름 `-r2`·`-r3`. 1차와 2차의 지적문이 같으면 3차를 하지 않고 멈춘다(§0.5 2번).
- 문 종료 코드 2(사용법·읽기 실패)나 도구 오류는 그림 문제가 아니다 → 멈추고 보고(§0.5 3번).
- 「문 없음」 항목(가림막·떼기 대부분, 틀 이전 원본의 편집, 틀 필요 예외 두 장)은 문을 돌리지 않고 「합격」 칸의 겹침·육안 기준만 본다. README에 「문 해당 없음」이라 적는다.

### 0.4 알려진 문 한계 — 띠 예외 (게임 쪽이 이미 판정한 것)

지금 문은 **띠**(배경 `bg_far`·`bg_mid`·`bg_near`, 장면 `scene_event`)를 틀의 절대 y 범위로만 잰다. 생성기는 띠를 조금 다른 높이나 다른 캔버스로 그리는 일이 잦고, V05 2차 판정에서 게임 쪽은 이런 띠(ES15·ES18 띠, ES01 열쇠 띠, H1 기본 장면 1983 × 793)를 **합격**시켰다. 2026-09-25 현재 이 네 장은 모두 문에서 FAIL이다. 그래서 띠 항목에만 아래 두 예외를 둔다.

| 예외 | 조건 (모두 맞아야 한다) | 할 일 |
| --- | --- | --- |
| **ㄱ 띠 위치** | ① `--spec`이 `bg_far`·`bg_mid`·`bg_near`·`scene_event` 가운데 하나. ② FAIL 줄이 `Only N% of the area outside the figures is clean background…`(background)와 `Remove the drawing outside the grid: N px…`(stray) **둘 가운데 것뿐**이다. ③ 눈으로 보면 그림이 가로 전체 폭의 **한 띠**이고(장면은 네 칸이 틈 없이 붙음), 띠 위아래가 깨끗한 자홍 한 색이며, 띠 안에 구멍·자홍 틈이 없다 | 다시 만들지 않는다. README에 `예외 ㄱ(띠 위치)`와 문 출력 전문을 적고 육안으로 간다 |
| **ㄴ 띠 캔버스** | ① ㄱ의 ①과 같음. ② FAIL 줄이 `The image must be exactly 1536x1024 pixels…`(canvas) 하나뿐이다(ㄱ의 두 줄이 함께 있어도 된다). ③ 편집이면 결과 크기 = 입력 크기(H1 계보는 1983 × 793). 생성이면 결과가 가로로 긴 한 띠(배경 약 4 : 1, 장면 약 8 : 1) + 위아래 자홍이다. ④ ㄱ의 ③ | 다시 만들지 않는다(「캔버스 크기는 띠 모양이면 도구가 맞춘다」 — V05 2차 판정). README에 `예외 ㄴ(띠 캔버스)`와 실제 크기를 적는다 |

- 위 줄 밖의 FAIL(`guide`·`alpha`·`fill`·`ground_band` 등)이 하나라도 있으면 예외가 아니다 → §0.3대로 다시 만든다.
- 조건이 맞는지 판단이 서지 않으면 예외를 쓰지 말고 멈추고 보고한다. 예외는 이 표의 두 가지뿐이다. 캐릭터·적·초상 시트에는 예외가 없다.
- H1 계보(입력 1983 × 793)는 캔버스 FAIL 때문에 문이 칸 검사를 하지 않는다. 그래서 H1 항목의 합격은 겹침·육안(W3·W6·W7)과 게임 쪽 15 §8.5 검사가 가진다.

### 0.5 멈춤 규칙

1. **배치 끝**(§3의 「여기까지 하고 보고」)에서 멈추고 README를 쓴다. 게임 쪽 판정이 README나 이 문서에 오기 전에는 다음 배치를 시작하지 않는다.
2. **한 항목이 막힘**: 세 번째 시도도 FAIL이거나, 1차·2차 지적문이 같거나, 편집이 요청한 곳 밖을 바꾸는 일이 두 번 되풀이되면 그 항목을 멈춘다. 그 항목을 입력·선행으로 쓰는 뒤 항목도 건너뛴다. 같은 배치의 다른 항목은 계속하고, 배치 끝에 함께 보고한다.
3. **바로 전체 멈춤**: 편집 결과의 크기가 입력과 다름 · 문 종료 코드 2 또는 도구 오류 · 입력 파일이 없음 · 저장소 파일을 고쳐야만 진행할 수 있음 · 문이 틀린 것으로 보임(§0.1 3번) · 서로 다른 두 항목에서 같은 FAIL 지적이 되풀이됨(구조 문제 신호 — 게임 쪽이 틀·수치·문장을 다시 본다).
4. 멈춤 보고에는 그 항목의 PNG 전부, 각 문 출력 전문, 보낸 글 전문, **한 줄 원인 추정**을 넣는다.

### 0.6 저장과 README 보고 형식

저장: `assets/_imagegen/v06/<파일>.png`(생성기 원본을 그대로 복사, 화소 손대지 않음) + `<파일>.prompt.txt`(보낸 글 전문) + `<파일>.gate.txt`(문 명령 한 줄 + 출력 전문, 문 있는 항목만) + 폴더 `README.md`.

`README.md` 형식(배치마다 위에 덧붙인다):

```markdown
## 배치 N · YYYY-MM-DD · 요약
| id | 파일 | 시도 | 문 | 예외 | 육안 | 인계 |
| V06-xx | <파일>.png | 1/3 | PASS·경고 7 / FAIL / 해당 없음 | 없음 / ㄱ / ㄴ | 합격 / 보류 | 인계 / 보류 / 멈춤 |

### V06-xx · <파일> · 시도 k
- 입력(넣은 순서): 입력 1 = <경로>, 입력 2 = <경로> …
- 보낸 글: <파일>.prompt.txt
- 크기: W × H (편집: 입력과 같음 / 다름)
- 원본 보존: 생성기 원본과 SHA-256 같음
- 문: `pnpm art:gate … ` → PASS / FAIL. FAIL 줄 전부(전문은 <파일>.gate.txt). 경고는 개수와 요점만
- 예외: 없음 / ㄱ / ㄴ (조건 ①~④를 어떻게 확인했는지 한 줄)
- 눈으로 본 결과: 「합격」 칸의 기준 번호마다 한 줄(E·W·SE 번호)
- 남은 차이:
- 인계: 인계 / 보류(이유) / 멈춤(이유)

## 멈춤 보고 (있을 때만)
- 항목, PNG 전부, 문 출력 전문, 보낸 글 전문, 한 줄 원인 추정
```
