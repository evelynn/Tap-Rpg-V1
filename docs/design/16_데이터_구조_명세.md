# 16 데이터 구조 명세

버전 0.2 · 작성일 2026년 9월 22일 · 상위 문서 00_문서지도.md, 01_핵심규칙_수치기준.md

게임을 이루는 데이터를 **정적 데이터**(콘텐츠 정의: 장소, 적, 장비, 특성, 사건 등)와 **동적 데이터**(저장: 가문, 인물, 가방, 일지, 진행 상태)로 나누어 구조를 정한다. 엔진에 의존하지 않도록 JSON으로 정의하며(00 O05), 규칙 구현자와 콘텐츠 작성자가 같은 필드 이름으로 이야기할 수 있게 하는 것이 목적이다. 수치의 출처는 01이고, 각 콘텐츠의 세부 값은 담당 문서가 정한다. 이 문서의 JSON 예시에 들어간 콘텐츠 값은 **구조 설명용**이며, 원문과 수치는 담당 문서가 확정한다.

**이 문서가 소유하는 규칙(00 §2.4)**: 데이터 형식, 효과·조건 문법, **템플릿 변수 등록표**(1.4절), **플래그 키 등록표**(5.2절). 판정 종류의 이름과 조합은 05 §6.1, 자동 선택 모델(태그·위험 등급·점수식)은 10 §5, 소모품 필드 값은 08 §4.2가 소유하며 이 문서는 그것을 데이터 키로 옮긴다.

**확정본(D37)**: 콘텐츠 정적 데이터의 형식은 개발 문서 `docs/dev/CONTENT_SCHEMA.md`(이하 **CS**)가 확정본이다. 팩 구조, 종류별 필드의 형식·필수 여부·기본값, 조건 단말·효과의 파라미터, 수정자 target, 코드 등록부, 검증 파이프라인은 CS에만 적는다. 이 문서와 CS가 다르면 CS가 우선한다. 이 문서는 형식 규칙(1절), 조건·효과·수정자의 **뜻**(3~4절), 템플릿 변수 등록표, 플래그 키 등록표, 저장 데이터(5절), 열거형(6절), 검증 목록(7절)을 둔다. CS가 이 문서의 절을 기준으로 삼는 표(2.5 item, 2.6 consumable, 2.6.1 material, 2.7 trait, 2.8 npc, 4.2 choice)는 이 문서에서 현재 스키마에 맞춰 유지하고, CS가 전체를 가진 표(balance, attitude, region, enemy, event 필드, 특성 훅)는 CS 절로 대신한다.

관련 문서: 01(수치·ID·공유 명칭), 04(행동 상태·목적지 고정), 05(판정 종류), 06(특성), 07(적·장소·재료), 08(장비·소모품·교체 제안), 09(생애·흡혈귀), 10(사건 시스템·자동 선택), 11(사건 원문), 12(계승·후손 반응), 13(저장 절차), 14(일지 문장·조사 규칙), 15(스프라이트 ID)

## 1 형식 규칙

### 1.1 파일 구성

정적 데이터는 **콘텐츠 팩**으로 둔다(DS-02). 첫 검증판 콘텐츠 전부가 기반 팩 `content/base/`이고, 새 시나리오·지역·사건은 코어 수정 없이 팩을 더해 넣는다. 게임과 시뮬레이터는 팩을 합쳐 검증한 **번들** 하나를 읽는다.

| 구분 | 경로 | 내용 |
| --- | --- | --- |
| 정적 | `content/{팩}/pack.json` | 팩 id·이름·버전·먼저 읽을 팩(`requires`) |
| 정적 | `content/{팩}/balance.json` | 01의 수치 상수, 05 §6.1 판정 종류 표(2.1절). 번들 전체에 하나 |
| 정적 | `content/{팩}/{종류 폴더}/*.json` | 종류별 정의(2절, 2.10절). 파일 하나에 정의 1개 또는 배열 |
| 정적 | `content/{팩}/events/{분류}/{ID}.json` | 사건 1개 = 파일 1개. 분류는 `life`·`chain`·`fate`·`system` |
| 정적 | `content/{팩}/flags.json` | 플래그 등록표(5.2절)를 옮긴 배열 |
| 정적 | `content/{팩}/patches/*.json` | 다른 팩 정의의 부분 수정(`merge` 하나뿐) |
| 동적 | `%APPDATA%\Tap\save\save.json` | 가문·인물·진행(13 §8.6) |
| 동적 | `%APPDATA%\Tap\settings.json` | 설치별 창 설정 |

- 종류 목록·폴더, 파일 규칙, 패치 규칙, 로드 순서와 번들 모양은 CS §1·§2가 정한다.

### 1.2 명명과 기본 타입

- 필드 이름은 `snake_case` 영어다. 열거값도 영어 소문자 `snake_case`다(6절 열거형 목록).
- 사람이 읽는 이름과 문장은 한국어 문자열을 그대로 넣는다. 첫 검증판은 다국어를 지원하지 않는다.
- 정적 데이터는 모르는 필드를 받지 않는다. 설명은 모든 객체에 둘 수 있는 `_note`·`_comment`에만 적는다(DS-03).
- 선택 필드는 **생략**으로 비운다. `null`은 CS가 `| null`로 적은 필드만 받는다.
- 공통 타입(전체와 코드 이름은 CS §3):

| 타입 | 형식 | 예 |
| --- | --- | --- |
| `id` | `^[A-Za-z][A-Za-z0-9_]*(-[A-Za-z0-9_]+)*$`. 종류 안에서만 고유(1.3절). 00 §2.2 접두사는 작성 관례 | `"W07"`, `"C01-3"`, `"D2"` |
| `uid` | 동적 개체의 고유 식별자. `"{접두}_{가문 내 일련번호}"` | `"it_000412"`, `"ch_0002"` |
| `flag_key` | `범위.snake_case`. 범위는 `life`·`fam`·`trip`(00 §2.2). 5.2절 등록표의 키만 쓴다. 키 묶음 자리에는 바인딩 `{place}`를 쓸 수 있다(3.4절) | `"fam.c01_rescue"`, `"life.l01_marked_{place}"` |
| `int` | 정수 | `12` |
| `ratio` | 0~1 실수. 비율·확률. **퍼센트·%p 값은 모두 ratio로 쓴다**(0.10 = 10%p) | `0.3` |
| `range` | `[최소, 최대]` 정수 배열, 양 끝 포함 | `[8, 16]` |
| `dice` | `NdM+K` 주사위 식 | `"2d6+1"` |
| `eff_min` | 유효 진행 분(실수, 소수 둘째 자리) | `213.75` |
| `utc_ms` | UTC 밀리초 정수 | `1790000000000` |
| `template` | 1.4절 문장 템플릿 문자열 | `"{name:이/가} 다리를 건넜다."` |
| `line` | 한 줄 기록 template. 길이 상한은 `balance.ui.line_max`(28자) | `"다리를 건넜다"` |
| `condition` | 3절 조건 표현식 | `{"age_gte": 35}` |
| `units` | 사건 보상 단위 배수(10 §6). 동전·경험치 단위 × 값 | `2` |

- 정수 퍼센트포인트 `pct_point`는 폐기했다(DS-29). 퇴각 기준 가산도 ratio다(`0.10`).

### 1.3 ID 참조 규칙

- 정적 데이터는 서로를 **ID로만** 참조한다. 이름 문자열로 참조하지 않는다.
- 동적 데이터는 정적 정의를 ID로(`def_id`), 동적 개체를 `uid`로 참조한다.
- **ID는 종류별 이름공간이다**(DS-01, D37). 같은 종류 안에서만 고유하면 되고, 참조 필드는 기대 종류를 선언해 그 종류에서만 찾는다(`item_id` → 장비, `location_id` → 장소). 방어구 `A01`과 모험 경로 `A1`, 확장 팩의 장소 `A10`과 방어구 `A10`은 서로 다른 정의다.
- 00 §2.2 접두사와 자릿수(장비 두 자리, 장소 한 자리)는 사람이 읽기 위한 **작성 관례**다. 로더는 ID 형식(1.2절)과 종류 안 중복만 검사한다. 확장 팩은 팩 고유 접두(`wf_`, `WF_`)를 권장한다.
- 연속 사건은 줄기 ID(`C01`, 종류 `chain`)와 단계 ID(`C01-3`, 종류 `event`)를 구분한다. 줄기 ID는 대문자·숫자·밑줄만 쓴다(파생 플래그 키를 만들기 때문, CS §5.9).
- 발견 지점(`A1-2`)·지도 조각(`A1-M1`)·시설(`smithy`)·던전 묶음·판정 종류 키처럼 다른 정의 안에 있는 이름도 종류별 이름공간을 가지며 참조 검사를 받는다(CS §1.3).
- 스프라이트 부품 ID는 15가 정한다(머리 `HR01~HR06`, 외형 계열 `V`, 효과 `FX`). 장소 접두 `H`와 겹치지 않는다(00 §2.2).
- 플래그는 항상 범위 접두를 포함한 전체 키로 저장·참조한다(`"fam.c01_rescue"`, `"c01_rescue"` 아님).

### 1.4 문장 템플릿 문법

이 절이 문법과 **변수 등록표**의 기준이다(00 §2.4). 문형과 사용 규칙은 14, 조사 판정 규칙은 14 §6이 정하고 이 문서는 그것을 구현한다.

#### 1.4.1 문법

- 변수: `{변수}`. 조사 붙이기: `{변수:받침형/무받침형}`. 예: `{name:이/가} {item:을/를} 내려놓았다.`
- 중괄호 문자를 그대로 쓰려면 `{{`, `}}`로 적는다.
- 변수 안에서 계산식을 쓰지 않는다(`{luck-2}` 불가). 계산 결과가 필요하면 별도 변수를 등록한다(`{luck_after}`).
- 등록표(1.4.3)에 없는 변수는 콘텐츠 검사 V5 오류다. 1.4.4 옛 표기도 등록하지 않으므로 V5 오류다(데이터로 옮길 때 정식 이름으로 바꾼다).
- 조사 쌍은 1.4.2의 9종만 쓴다. 9종 밖의 쌍, 중괄호 짝 불일치, 비었거나 공백이 든 변수 이름은 V5 오류다.

#### 1.4.2 조사

| 표기 | 받침 있음 | 받침 없음 | ㄹ 받침 | 병기형(판정 불가) |
| --- | --- | --- | --- | --- |
| `{x:이/가}` | 이 | 가 | 이 | `이(가)` |
| `{x:은/는}` | 은 | 는 | 은 | `은(는)` |
| `{x:을/를}` | 을 | 를 | 을 | `을(를)` |
| `{x:과/와}` | 과 | 와 | 과 | `과(와)` |
| `{x:으로/로}` | 으로 | 로 | **로** | `(으)로` |
| `{x:아/야}` | 아 | 야 | 아 | `아(야)` |
| `{x:이랑/랑}` | 이랑 | 랑 | 이랑 | `(이)랑` |
| `{x:이나/나}` | 이나 | 나 | 이나 | `(이)나` |
| `{x:이라/라}` | 이라 | 라 | 이라 | `(이)라` |

**받침 판정(판정 대상 글자, 한글·숫자·영문, 병기형을 쓰는 경우)은 14 §6이 단일 출처이며 이 문서는 그것을 그대로 구현한다.** 위 표의 `ㄹ 받침` 열은 `으로/로`만 받침 없음처럼 다루고(`로`), 나머지 조사는 받침 있음과 같다는 뜻이다.

#### 1.4.3 변수 등록표

## 2 정적 데이터

### 2.1 balance

01의 수치를 섹션별로 담는 정의 하나(id `balance`)다. 코드에 수치를 박지 않고 여기서 읽는다. **섹션·키 전체와 기반 팩 값은 CS §5.1**이 확정본이다. 모든 섹션과 키가 필수이고, 확장 팩은 패치로만 바꾼다.

| 섹션 묶음 | 섹션 | 출처 |
| --- | --- | --- |
| 시간·날씨 | `time`(계절 순서 포함), `weather`(계절별 가중치, 날씨별 효과 수정자) | 01 §1 |
| 인물 | `actions`, `stats`, `growth`, `reference_character`, `aging`, `skills`, `xp` | 01 §1.2·§2, 05 |
| 판정·전투 | `check`(가벼운 곤란 표 포함), `check_kinds`(6.13절), `combat`, `enemy_formula` | 01 §3~§5, 05 |
| 회복·패배 | `recovery`, `injury`, `defeat`(구조자 표, 사망 제안) | 01 §6, 07 §8 |
| 위험·경제 | `risk`, `economy`, `equip_eval` | 01 §7·§9, 08 |
| 계승 | `inheritance` | 01 §14, 12 |
| 사건·행동 | `events`, `choice_ai`, `activity_ai`, `first_sortie`, `dungeon`, `adventure` | 04, 07, 10 |
| 화면·저장 | `ui`, `offline` | 01 §15·§16, 13 |
| 전문화·방침·생애 단계 | `specializations`, `policy_defaults`, `life_stage_rules` | 05 §8, 01 §18.2, 09 §1.2 |

- **같은 수치는 한 곳에만 둔다**(00 §2.4). 생애 단계 경계 나이는 `aging.life_stages`의 `from_age`가 단일 출처이며 `offline`에 경계 목록을 따로 두지 않는다(I10). 흡혈귀 수치는 TM01 정의의 `mutation`, 자녀 후보 최대 수는 S02 사건의 `max_per_life`에만 둔다.
- 날씨 효과는 `weather.effects`의 날씨별 수정자 목록이다(DS-34, 값은 01 §1.3 그대로). 눈의 야영 피로 변화는 수정자 `camp_fatigue_add` +10(−40 → −30)이다.
- 판정 종류 `check_kinds`의 난이도는 구조화한 `dc {kind: region | fixed | event | enemy_ac | level_formula}`다(DS-22). 사건이 쓸 수 있는 `dc`·`dc_offset`은 4.2절.
- 길드 순찰 구역은 balance가 아니라 장소의 `patrol_zone`이다(DS-05, 2.3절).
- 첫 출정 보장(D21)은 사건 필드가 아니라 `first_sortie`(목적지·조우 수·보장 드롭·보장 사건)다(DS-31).
- 사망 원인 기록의 다음 세대 제안(07 §8.3)은 `defeat.death_suggestions {max, rules[{ctx, value?, text}]}`다. 관문별 문장은 장소의 `gate.lines`(DS-33).
- `balance` 안의 ID 참조(첫 출정 장소·보장 장비·보장 사건, 시작 소지품, 지원 장비, 대체 보호자 NPC, 기본 태도)도 참조 검사를 받는다. 코어 코드는 이 값을 읽을 뿐 ID를 쓰지 않는다.
- 01 §17 밸런스 검증 목표 범위는 balance 밖(시뮬레이터 기대값)이다.

### 2.2 attitude (태도)

태도 3종(`stable` `adventurous` `challenging`)은 열거가 아니라 **데이터 종류**다(DS-04). **필드 전체와 값은 CS §5.2**다. 값의 출처는 01 §7.1(가중치·퇴각·피로·위험·관문 한도·예약금), 04(목표 조우·장면 수·장소 목표 위험 차·적정도 계수), 07 §5.5·§5.6(안전 계수·관문 체력), 08 §4.1·§7.4·§8(구매 목표·교체 배수·경상 치료), 10 §5(태그 점수·위험 보정)다.

- 회복약만 적던 `potion_target`은 소모품 묶음별 구매 목표 `buy_targets {potion, ration, bandage, moon_wine}`로 바꿨다(DS-11, 08 §4.1 표 전체).
- 적정도 계수 `fit_coef`는 04 §5.2 표를 태도별로 옮긴다(D40).

### 2.3 region (장소)

장소는 `kind`(`town` / `hunting_ground` / `dungeon_floor` / `adventure_route`)로 필드가 갈리는 판별 유니온이다. **필드 전체와 A1·관문 예시는 CS §5.3**이다.

| 바뀐 점 | 내용 |
| --- | --- |
| 순찰 구역 | `guild_patrol` → `patrol_zone`(F6·F7·F8 항상 통과, H1·A1). 모든 후보가 탈락했을 때의 목적지는 `fallback`(H1)(DS-05) |
| 발견형 해금 | `discovered_kind` 표시를 폐기한다. 후손 면제형 해금(12 §7.4)은 조건 단말 `discovered`(가문 발견 목록)로만 쓴다. 예: H2 `{"any":[{"level_gte":3},{"discovered":"H2"}]}`(DS-06) |
| 던전 순서 | 층은 `dungeon {group, depth}`로 순서를 정한다. 층 순서와 "더 깊은 층"을 ID가 아니라 이 값으로 계산한다(DS-20, D44) |
| 관문 | `gate_enemy_id`·`gate_lethal` → `gate {enemy_id, lethal, remnant, first_clear, lines}`. `lines`는 관문 앞 귀환·치명 차단·사망 제안 문장(07 §5.6·§8.3)(DS-33) |
| 던전 표 | 함정 표 `trap_table`, 보물 표 `treasure_table`, 조용한 갱도 문장 `quiet_line` |
| 모험 경로 | 장면 가중치 `scene_weights`, 발견 지점 `discoveries[]`, 지도 조각 `map_fragments[]`(ID `A1-M1`형, DS-28) |
| 그 밖 | 길드 지원 후보 `aid_allowed`, 적자 판단 제외 `deficit_exempt`, 계승 때 닫힘 `closes_on_succession`(A4), 패배 구조자 표 `rescuers`, 지형 요소 후보 `feature_words` |

#### 2.3.1 facility (마을 시설)

마을의 `facilities[]`는 `{id, name, npc_id, good_stock?, services?}`다. 시설 `id`(`smithy`, `general_store`, `guild`, `inn`, `clinic`)는 종류별 이름공간 `facility`이고 효과·장비가 이 id를 가리킨다. **판매 목록 `stock`은 폐기했다**(DS-42). 판매 선언은 장비의 `shop`(2.5절)과 소모품의 `shop`(2.6절)에만 두고, 진열은 엔진이 시설별로 거꾸로 모아 만든다(재고 규칙은 08 §5). 새 장비 팩은 마을을 패치하지 않는다.

### 2.4 enemy (적)

**필드 전체는 CS §5.4**, 특수능력 13종은 CS §4.4다. 수치는 01 §5.2 등록부 값이며 `balance.enemy_formula`로 다시 계산한 값과 다르면 V17 경고다.

- 계열 `family`는 열거가 아니라 데이터 종류 `enemy_family`(`rat` `wolf` `bat` `kobold` `unique`, 표시 이름 `{enemy_kind}`)를 가리킨다(DS-04).
- `specials[]`는 `{kind, ...파라미터}` 판별 유니온이다. 특정 장비·특성 ID를 파라미터에 넣지 않고, 무효화는 수정자(`fear_immunity`, `dark_penalty_ignore`, `special.{kind}.{param}` 가산)로 쓴다. 의도적 예외의 사유는 `_note`에 적는다(DS-03).
- 승리 문장 `victory_lines`(2개 이상)와 퇴장 연출 `exit_line`을 둔다(07 §4.1·§4.2, DS-33).
- `level`·`hp` 등은 레벨 오프셋 0일 때의 값이다. 던전 방·밤 출정·관문 잔당처럼 레벨이 오른 적은 `enemy_formula`로 다시 계산한다.

## 3 조건과 수정자

### 3.1 조건 표현식 문법

조건은 JSON 객체다. 결합자와 단말(leaf)로 이루어진다.

| 형태 | 뜻 | 예 |
| --- | --- | --- |
| `{"all": [c1, c2, ...]}` | 모두 참 | `{"all":[{"age_gte":35},{"age_lt":65}]}` |
| `{"any": [c1, c2, ...]}` | 하나 이상 참 | `{"any":[{"attitude":["adventurous","challenging"]}]}` |
| `{"not": c}` | 부정 | `{"not":{"mutation":"vampire"}}` |
| `{단말키: 값}` | 단말 조건 | `{"season":["winter"]}` |
| `{"num": {"key", "op", "value"}}` | 일반 수치 비교. `op`: `==` `!=` `>=` `>` `<=` `<` | `{"num":{"key":"stat.soc","op":">=","value":3}}` |
| `true` / `false` | 상수 | `true` |

- 빈 `all`은 참, 빈 `any`는 거짓이다.
- 단말 객체에 키가 둘 이상이면 로드 오류다. 여러 조건은 `all`로 묶는다.
- 조건 평가는 부수 효과가 없고 **난수를 쓰지 않는다**. 확률 분기는 효과 `chance`(4.3절)가 담당한다.

### 3.2 단말 조건 종류 (56종)

이 표는 단말 조건의 **뜻**이다. 파라미터의 정확한 형식(참조 종류, 선택 필드)은 CS §4.1이 확정본이다. `id`로 적은 값은 그 종류의 ID 참조다.

| 키 | 값 형식 | 뜻 |
| --- | --- | --- |
| `age_gte` / `age_lt` | int | 현재 나이 비교 |
| `level_gte` / `level_lt` | int | 레벨 비교 |
| `life_stage` | enum[] | `novice` / `prime` / `veteran` / `elder` |

### 3.3 수정자(modifier)

특성·장비·전문화·변이·부상·나이·일시 효과·날씨는 모두 같은 수정자 구조로 표현한다.

| 필드 | 형식 | 필수 | 설명 |
| --- | --- | --- | --- |
| `target` | string | O | 적용 대상 키(아래 표) |
| `op` | enum | O | `add` / `mul` / `set` / `flag` / `charges_per_sortie` / `charges_per_life` / `charges_total` |
| `value` | number, bool 또는 string | O | target의 값 종류에 맞는 값(수: `add`·`mul`·`set`, bool: `flag`, 충전: 정수 ≥ 1, 문자열: `set`) |
| `when` | condition | - | 이 조건일 때만 적용 |

이 표는 target의 **뜻**이다. target 패턴 전체(신설 포함 약 60종), 값 종류와 허용 op, 합산 target(`hp_max_mult`·`price_mult`·`sell_mult`는 `add`만), 고정 target(`recovery_coef`·`defeat_item_loss_chance`는 `set`만)은 CS §4.3이 확정본이다.

| target | 뜻 |
| --- | --- |
| `stat.{x}` | 능력치 가산(상한 규칙 01 §2.1) |
| `check.{kind}` | 판정 종류별 보정. kind는 `balance.check_kinds`의 키(6.13절) |
| `check.stat.{x}` / `check.skill.{x}` | 그 능력치·숙련을 쓰는 모든 판정(예: TI05 먼지 장소 의지 판정 −1, 비·안개 탐색 −1) |
| `check.all` | 모든 판정(피로 −1, 흡혈귀 낮 −2, `trip.fear` −1 등) |
| `hit` / `hit_vs.{family}` | 명중 |
| `damage` / `damage_vs.{family}` / `damage_mult` | 피해 |
| `ac` | 방어 |
| `hp_max_add` / `hp_max_mult` | 최대 체력 |
| `rest_recovery_mult` | 휴식 회복량 |
| `fatigue_gain_mult` | 피로 획득(`when`으로 장소 꼬리표 지정) |
| `travel_time_mult` | 이동 시간(감소 합계 최대 −40%, 05) |
| `discovery_chance_add` / `discovery_chance_mult` | 모험 발견 확률 |
| `trap_encounter_add` | 함정 조우 확률 |
| `treasure_room_chance_add` | 다음 던전 방이 보물 방일 확률 |
| `drop_chance_add` | 장비 드롭 확률 가산(ratio, `trip.rat_luck` 0.02) |
| `xp_mult` | 경험치 배수(`trip.rain_hunt`) |
| `coin_mult` | 동전 배수 |
| `retreat_hp_add` | 퇴각 기준 가산(ratio, 0.10 = 10%p). 특성 훅 `retreat_hp_add`와 더한다 |
| `activity_weight.{hunt\|adventure\|dungeon}` | 활동 가중치 |
| `location_score.{장소 ID}` | 04 §6.1 장소 점수 가산(사건의 1회 가산 등). 장소 자리에 바인딩을 쓸 수 있다(3.4절) |
| `price_mult` / `sell_mult` / `inn_cost_mult` / `food_cost_mult` / `maintenance_mult` | 경제(할인 상한 −20%는 08 §5, 사건 특가 제외) |
| `shop_surcharge` | 상점 가격 가산(흡혈귀 낮 귀환 +20%, 09 §7.4. F03 단서 면제는 이 수정자의 `when`) |
| `reserve_add` | 예약금 비율 가산(ratio) |
| `defeat_loss_mult` | 일반 패배 손실 비율(J01: 0.4 → 50% × 0.4 = 20%) |
| `mining_reward_mult` | 광맥 채취 보상(W05) |
| `luck_drop_add` | 희귀 드롭 가중 |
| `thirst_gain_mult` | 갈증 증가 배수(09) |
| `fear_immunity` / `dark_penalty_ignore` | 면역·무시(`op: flag`) |
| `ambush_negate` | 매복 무효 충전(W07) |
| `escape_on_defeat` | 패배·치명 탈출 충전(R01) |
| `serious_heal` | 중상 즉시 치유(R03, `charges_total: 1`) |
| `enemy_hit_first_round_add` | 관문 첫 라운드 적 명중 보정(W10) |
| `night_damage_mult` / `day_fatigue_mult` | 시간대 보정(R04, 흡혈귀) |

- 이 표 밖의 신설 target(CS §4.3): `first_round_hit_add` `first_strike_hit_add` `pair_damage_taken_mult` `breather_mult` `recovery_coef` `camp_hp_mult` `camp_fatigue_add` `travel_sec_add.{장소}` `descend_sec_add.{장소}` `return_travel_time_mult` `travel_fatigue_add` `ambush_chance_add` `encounter_weight_mult.{family}` `defeat_item_loss_chance` `equip_eval_mult` `forage_reward_mult` `final_check_add` `second_wind_ratio` `special.{특수능력}.{파라미터}` `camp_raid_immunity` `rescuer_override` `second_wind`.
- `camp_fatigue_add`는 야영 피로 변화(−40)에 더하는 값이다(눈 +10 → −30, DS-34). 옛 이름 `camp_fatigue_recovery_add`는 쓰지 않는다.

수정자 합산 순서: `(set 값 또는 기준값) + Σadd`, 그 뒤 `× Πmul`. 판정 보정은 합산 뒤 01 §3.1의 −5~+5로 자른다. 특성 하나의 판정 보정은 ±2까지다(06).

### 3.4 자리 바인딩 `{place}`

키 묶음 플래그(5.2절 `life.l01_marked_{place}`)와 장소 자리를 가진 target·num 키·효과 파라미터는 **평가 시점의 장소**를 가리켜야 한다. 데이터에는 장소 ID 대신 바인딩을 적고, 엔진이 효과를 적용하거나 조건을 평가할 때 장소 ID로 바꾼다(DS-36). 문법은 템플릿 변수 표기와 같다.

| 바인딩 | 뜻 |
| --- | --- |
| `{place}` | 평가 문맥의 장소: 출정 중이면 현재 장소, 사건이면 그 사건이 일어난 장소, 사망 기록이면 사망 장소. 템플릿 변수 `{place}`와 같은 값 |
| `{그 사건의 장소 변수}` | 그 사건 `context_vars`가 채운 장소 변수(`{rumor_place}`, `{target_place}`). 사건 정의 안에서만 쓴다 |

- 쓸 수 있는 자리: 플래그 키의 꼬리(`flag` 조건, num `flag.` 키, `set_flag`·`clear_flag`·`set_family_flag`·`set_trip_flag`·`clear_trip_flag`), target·num 키의 장소 자리(`location_score.{rumor_place}`, `counter.safe_returns.{place}`), 장소 파라미터(`temp_mod.location`, `dungeon_mod.location`, `counter_add.where`).
- 저장되는 값은 언제나 치환된 키다(`life.l01_marked_H1`). 사건 밖(장비·특성·balance)에서는 `{place}`만 쓴다(V19).
- 예: L01 `돌탑을 쌓아 둔다`는 결과 `{"type":"set_flag","key":"life.l01_marked_{place}"}`, 사건 가중 `{"when":{"flag":"life.l01_marked_{place}"},"mult":3}`, 채집 판정 `situational` `{"target":"check.all","op":"add","value":2,"when":{"flag":"life.l01_marked_{place}"}}`로 적는다.

### 4.1 event 필드

필드의 의미는 10 §2가 정한다. **필드 전체와 형식은 CS §5.10**이 확정본이다. 아래는 이름과 뜻의 지도다.

| --- | --- | --- |

| 장소 | `locations`(선택), `location_match`(선택) | 발생 장소 ID 목록 또는 장소 거르개(3.2절). **둘 다 없으면 모든 장소**(DS-32). 여러 장소 공통 생활 사건은 `location_match`로 쓴다 |
| 시점 | `triggers` `life_stages` `seasons` `time_of_day` | 판단 지점(6.10절, 둘 이상 가능), 생애 단계·계절·출정 시간대 제한 |

| 도입 | `intro {lines, detail?, tag, animation?, family_variants?}` | 한 줄 기록 2변형 이상(≤28자, 과거형), 상세, 태그, **순서 있는 동작 배열** `[{action, props?, sec?}]`(DS-52, 동작 키는 01 §18.4), 가문 변형 |
| 선택지 | `choices` | 1개 이상. 선택 없는 사건은 선택지 1개(`id: "auto"`) |
| 장면 | `scene`(선택) | 풍경 영역 전용 장면 id(`ES01`~`ES20`, 15 §9.3, D63. `ES21` 계승 출발은 사건이 아니라 계승 연출이 쓴다, D76). 없으면 동작·소품 연출만. M2에서 스키마(CS §5.10)와 콘텐츠에 넣는다 |

- 확정 발생 필드 `guaranteed`는 폐기했다. 첫 출정 보장(D21)은 `balance.first_sortie`가 가진다(DS-31).
- 흡혈귀 제외처럼 사건마다 복사되던 규칙은 사건 `condition`(`thirst_stage_gte`, `mutation`, `last_trip_time`)으로 쓰고, 흡혈귀 낮 출정 야영 사건 제외는 TM01 `mutation.blocked_triggers`가 판단 지점 단위로 한 번에 거른다(10 §4.1).

### 4.2 choice, check, combat, outcome

CS §5.10이 이 절을 기준으로 삼는다.

**choice**

| 필드 | 형식 | 필수 | 설명 |
| --- | --- | --- | --- |
| `id` | string | O | 사건 안에서 고유. `snake_case` |
| `label` | string | O | 선택지 문구 |
| `short` | string | hold=none O | 과거형 요약. 이유 문장의 `{choice_short}`(10 §5.6) |
| `tags` | enum[] | hold=none O | 성격 태그 1~2개: `safe` `thrift` `rest` `kindness` `info` `new_path` `reward` `bold`(10 §5.1) |
| `risk` | enum | O | 선택지 위험: `none` `low` `medium` `high` `lethal`(10 §5.4). 실패 시 가장 나쁜 결과로 정한다. `lethal`은 첫 검증판에서 쓰지 않는다(V10) |
| `requires` | condition | - | 이 선택지가 보이는 조건 |
| `check` | check | - | 판정. `combat`과 함께 쓰지 않는다 |
| `combat` | combat | - | 선택지 자체가 전투일 때 |
| `starlight` | bool | - | 별빛 길(D78, 10 §8.3). 가호 `숨은 길을 비춘다` 전에는 `choices_visible`에 넣지 않고, 자동 선택·사전 방침이 고르지 않는다 |
| `decline` | bool | - | 안전한 종료 선택지. `새로운 운명 제안은 거절하고 계속` 방침이 고른다(F01 `아직은`, F02 `그대로 돌아선다`, F03 `잔을 내려놓는다`) |
| `preview` | object | hold≠none O | 선택 창 칸 `{benefit, cost, reversible}`(10 §8.3). 판정이 있으면 창이 능력치·숙련·난이도·성공 확률을 덧붙인다 |
| `outcomes` | object | O | 키: `crit_success` / `success` / `partial` / `failure` / `crit_failure` / `always` / `win` / `defeat` / `stalemate`. 판정이 있으면 `success`·`failure`, 전투면 `win`·`defeat`가 필수이고, 둘 다 없으면 `always`만 쓴다 |

- 자동 선택 점수는 저장하지 않는다. 엔진이 `tags`·`risk`·판정 성공 확률과 태도(`tag_scores`, 2.2절), 특성(`choice_tag_bonus`)으로 매번 계산한다(**10 §5 참조**). 11의 `안·모·도` 열은 표준 조건 계산 결과를 적어 둔 것이며 데이터에 넣지 않는다.
- 사건마다 `risk`가 `none` 또는 `low`인 선택지가 최소 하나 있어야 한다(V7). 선택지가 1개인 시스템 자동 사건은 `tags`·`short`를 생략한다(DS-53).
- 특성 반응(11 각 사건)은 새 필드 없이 판정 `situational`의 `when {has_trait}`, 선택지 `requires`, 효과 `when`으로 쓴다.

**check** (판정 종류의 능력치·숙련·부분 성공 기본값은 05 §6.1 → 6.13절 `check_kinds`에서 읽는다. 사건이 조합을 새로 만들지 않는다)

| 필드 | 형식 | 설명 | 예 |
| --- | --- | --- | --- |
| `kind` | 판정 종류 키 | `balance.check_kinds`의 키(6.13절). `any_of`와 둘 중 하나 | `"force"` |
| `any_of` | 키 2개 | **선택형 판정**(05 §6.1): 보정 합이 높은 쪽으로 한 번 굴린다. 같으면 앞의 것 | `["lore","persuade"]` |
| `dc` | int | 고정 DC. `dc_offset`과 함께 쓰지 않는다 | `16` |
| `dc_offset` | int | 지역 기준 DC(01 §3.2) + 종류 가감 + 값. 마을 사건은 인물 레벨 기준 | `2` |
| `partial_allowed` | bool | 종류 기본값을 **끄는** 용도로만 쓴다. 기본값이 불가인 종류를 켤 수 없다(`attack_event`는 사건이 정함) | `false` |
| `situational` | modifier[] | 이 판정에만 붙는 상황 보정(`when` 가능) | `[{"target":"check.all","op":"add","value":2,"when":{"flag":"life.c01_map_read"}}]` |

- 사건이 쓸 수 있는 `dc`·`dc_offset`은 종류의 난이도 모양(`check_kinds.*.dc.kind`)에 따른다: 지역 기준 종류는 `dc_offset`(생략하면 0) 또는 `dc`(고정값으로 덮어씀), 고정 종류(흥정 12)는 생략하거나 `dc`로 덮어씀(`dc_offset` 금지), 사건 결정 종류(설득·인연·전승 기억·저주 저항)는 `dc` 또는 `dc_offset` 필수, 공식·적 방어 종류(도주·부상·최후·명중)는 사건에서 쓰지 않는다(V20, CS §5.10).

`crit_success`·`crit_failure`가 없으면 각각 `success`·`failure`를 쓴다(대성공 보상 +50%는 05 §6.4). `partial`이 없으면 부분 성공 구간은 실패로 처리한다.

**combat**

| 필드 | 형식 | 설명 | 예 |
| --- | --- | --- | --- |
| `enemies` | object[] | `{enemy_id}`, `{by_location: {장소 ID: 적 ID}}`, 또는 `{from_region_table: true}`(현재 장소 조우 표에서 뽑음, 경보 종줄 함정, DS-27) | `[{"by_location":{"H2":"EN03","A2":"EN03","H3":"EN04"}}]` |
| `count` | int 또는 `[{when, count}]` | 적 수. 조건별 수 | `[{"when":{"level_lt":8},"count":1},{"when":true,"count":2}]` |
| `sequential` | bool | 여러 적을 한 체씩 연속으로 | `true` |
| `first_strike` | enum | `char` / `enemy` / `default`(01 §4) | `"char"` |
| `ambush` | bool | 매복 취급(기본 false): 매복 대응 판정을 하고 실패하면 적 선공 + 1라운드 적 명중 +2(05 §7.3) | `true` |

### 4.3 효과 종류 (53종)

| `on_town_return` | `effects`(effect[]), `line`(선택) | 다음 마을 도착 때 적용(C01-3 귀환 시 W07 전달·TA01 획득) |
| `schedule_event` | `event_id`, `at`(`next_town_return` / `next_camp` / `eff_min`), `after_min`(`eff_min`이면 필수) | 후속 사건 예약. 예약된 사건은 발화할 때 `condition`만 검사한다 |
| `reopen_choices` | `exclude`(선택지 id[]), `situational`(선택) | 같은 선택 창을 일부 선택지를 빼고 다시 연다(F03 사연 묻기) |

**기록·관계·연출**

| type | 파라미터 | 설명 |
| --- | --- | --- |
| `npc_relation` | `npc_id`, `delta` | 인연 수치 −100~100 |
| `skill_use` | `skill`, `count` | 숙련 사용 횟수 가산(판정 있는 선택지의 +1은 자동, 10 §6.2) |
| `family_record` | `kind`(`chronicle`/`bond`/`codex`), `key`, `text` | 가문 기록 |
| `unlock_family` | `kind`(`background`/`appearance`), `id` | 가문 해금(12 §8). 연대기 칭호는 업적 보상 `{kind: "title", text}`로만 준다(`title` 폐기, DS-47) |
| `journal` | `tag`, `line`, `detail`(선택), `importance`(선택) | 결과 문장 외 추가 기록 |
| `animation` | `action`(01 §18.4의 데이터 키, `cheer` 등), `props`(소품 id[], 선택) | 연출 지시. 오프라인 정산에서는 무시(DS-09) |

`start_chain`은 폐기하고 `advance_chain {stage: 1}`로 대신한다. 50종에 `remove_consumable`·`add_material`·`roll_check`를 더해 53종이다. 비용 표시가 필요한 효과(V8: `mutate`·`extend_lifespan`·`remove_item(chosen_relic)`·`life_stat_add`)의 목록은 코드 등록부 옆에 둔다(CS §4.2).

### 5.2 플래그 키 등록표

**이 표가 플래그 키의 유일한 등록표다**(00 §2.4). 문서와 데이터는 이 표의 키만 쓴다. 새 키는 여기 먼저 등록한다.

- 형식: `범위.snake_case`. `{place}`·`{kind}`·`{role}`이 붙은 키는 뒤에 장소 ID·종류 키를 이어 붙인 **키 묶음**이다(예: `life.l01_marked_H1`). 데이터에는 `_{place}`를 그대로 적고 엔진이 평가 시점의 장소 ID로 치환한다(3.4절). `{kind}`·`{role}` 자리는 선택지·은퇴 역할마다 값이 정해져 있으므로 데이터에 리터럴 키를 적는다.
- 연속 사건 줄기의 자동 키(`life.{chain}_stage`, `fam.{chain}_done`, `fam.{chain}_{outcome}`, `fam.{chain}_unfinished`)는 줄기 정의에서 로더가 파생 등록한다(CS §5.9). 아래 표의 C01·C02 키는 그 결과를 보인 것이다.
- 데이터로는 이 표를 `flags.json`(CS §5.8)으로 옮긴다. 출정 플래그의 수치 효과는 그 정의의 `trip_modifiers`가 단일 출처다(DS-46).
- 저장 위치: `fam.` → `family.flags`, `life.` → `character.flags`, `trip.` → `current_activity.sortie.trip_flags`. 모두 전체 키 그대로 저장한다.
- 수명: `fam.`는 영구 보존(반응 기간이 끝나도 지우지 않음, 12 §7.6), `life.`는 생애 종료 시 연대기로 옮기고 지움, `trip.`는 출정 종료 시 지움.

### 7.2 콘텐츠 작성자용 검증 목록

정적 데이터를 바꿀 때 검증 도구(`pnpm content:check`)로 모두 통과해야 한다. 검사 단계는 팩 구조(P01~P09) → 스키마(S01) → 참조·의미(V) 순서이고, 앞 단계에 오류가 있으면 뒤 단계를 하지 않는다. 오류 코드, 심각도, 메시지 형식, 각 V의 구현 위치는 CS §7이 정한다.
