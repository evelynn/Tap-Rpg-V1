# @tap/art-check

픽셀 에셋 자동 검사기. `docs/art/assets.manifest.json`이 정한 규격과 실제 PNG 화소를 대조한다.
Node 22 내장 모듈만 쓴다(새 npm 패키지 없음). PNG는 직접 해석한다 — 시그니처·IHDR·PLTE·tRNS를 읽고
IDAT를 `node:zlib`의 `inflateSync`로 푼 뒤 스캔라인 필터(0~4)를 복원해 8비트 RGBA로 정규화한다.

## 실행

제작 원본(이미지 생성물, `assets/_imagegen/`)은 `inspect`로 사실만 본다. 원본은 규격과 달라도 된다(설계 결정 D56). `check`는 M2 에셋 로더가 정규화한 게임 규격 파일의 합격 판정용이다.

```bash
# 매니페스트 전수 검사
pnpm exec tsx tools/art-check/src/cli.ts check

# 우선순위·항목만 추려서
pnpm exec tsx tools/art-check/src/cli.ts check --priority P0
pnpm exec tsx tools/art-check/src/cli.ts check --id chr_body_base_48 --id fx_shadow_48

# 기계용 출력 / 미제작도 실패로 세기 / 아직 안 그린 칸은 경고로만
pnpm exec tsx tools/art-check/src/cli.ts check --json
pnpm exec tsx tools/art-check/src/cli.ts check --require-all
pnpm exec tsx tools/art-check/src/cli.ts check --id chr_body_base_48 --allow-empty

# 매니페스트에 없는 PNG의 사실만 세기(크기·알파·색 수·정수 격자)
pnpm exec tsx tools/art-check/src/cli.ts inspect output/pixel-art-v01/images
```

- `--manifest <경로>` 기본값 `docs/art/assets.manifest.json`.
- `--root <경로>` 산출물 트리의 뿌리. 기본값은 매니페스트의 `defaults.root`(= 저장소 뿌리).
- 종료 코드: `0` 오류 없음 · `1` 오류 있음 · `2` 사용법·읽기 실패.

## 검사 항목

| 코드 | 검사 | ASSET_ORDERS 0.9절 대응 |
| --- | --- | --- |
| M0 | PNG를 읽을 수 있는가 | — |
| M1 | 크기가 규격과 같고 칸 크기로 정수 나눗셈이 되는가 | A5 |
| M2 | 칸 가장자리 `margin`px 안에 내용이 없는가(칸 밖 침범·이웃 칸 접촉) | A6, A9 |
| M3 | 알파가 허용값(기본 0·255)뿐인가 | A2 |
| M4 | 고유 색 수가 전체·칸별 상한 안인가 | A4 |
| M5 | 모든 색이 팔레트 안인가(위반 색과 화소 수를 돌려준다) | A3, A18 |
| M6 | 내용이 있어야 할 칸이 비었거나, 비어야 할 칸에 내용이 있는가 | 0.6절 |
| M7 | 동반 JSON(`.anchors.json`·`.frames.json`·`.9slice.json`)이 있고 형식이 맞는가 | A10 |
| M8 | 기준점이 칸 안에 있는가 | A10 |

M1이 실패하면 칸 단위 검사(M2·M4 칸별·M6)는 돌리지 않는다. 격자가 없으면 칸 좌표가 뜻을 잃기 때문이다.

`chr_body_base_48`처럼 한 시트를 카드 여러 장(AO-02~AO-10)이 나눠 채우는 동안에는 `--allow-empty`를 붙인다.
그러면 「내용이 있어야 하는데 빈 칸」만 경고가 되고, 「비어야 하는데 내용이 있는 칸」은 그대로 오류로 남는다.
시트를 다 채운 뒤에는 플래그 없이 다시 돌려 종료 코드 0을 받아야 한다.

## 생성 원본 정규화 (`normalize` · `preview` · `layers`)

D56에 따라 그림은 이미지 생성 모델이 만든 큰 PNG(예 1536×1024, 단색 `#FF00FF` 배경 또는 투명 배경, N열 × M행 등간격 격자,
칸 하나에 포즈 하나)로 들어온다. 이것을 게임 규격 시트(논리 칸 48×48·32×32·32×24…, 알파 0/255, 팔레트 색, 인덱스 PNG)로
바꾸는 것이 게임 쪽 담당이고, 이 세 명령이 그 도구다. 원본은 손대지 않고 읽기만 한다.

```bash
pnpm art:normalize            # docs/art/imagegen.map.json의 모든 항목 → assets/game/<이름>.png + <이름>.json
pnpm art:normalize --name ref_actions18_48
pnpm art:preview              # assets/game/_preview/ 에 ×4 검수 확대본

# 레이어 정합 측정(대응표 이름 또는 원본 PNG 경로). 한 칸이라도 기준을 넘으면 종료 코드 1
pnpm exec tsx tools/art-check/src/cli.ts layers ref_actions18_48 body_actions18_48 hair_actions18_48 sword_actions18_48
pnpm exec tsx tools/art-check/src/cli.ts layers ref_actions18_48 assets/_imagegen/v03/19-cloth-actions18-48-r2.png \
  --clothing assets/_imagegen/v03/19-cloth-actions18-48-r2.png   # 불합격 천옷 → 실패(종료 1)
```

`assets/game/`은 생성 산출물이라 저장소에 넣지 않는다(`.gitignore`). 언제든 원본과 대응표에서 다시 만든다.

### 대응표 `docs/art/imagegen.map.json`

v04 원본(투명 배경)은 두 번째 대응표 `docs/art/imagegen.v04.map.json`(산출 `assets/game/v04/`)에 있다: 걷기 12, 기준 D·E와 몸체 D·E·피격 검 c13, NPC 11, 늑대(창 모형의 적).

| 키 | 뜻 |
| --- | --- |
| `source_dir` · `out_dir` | 원본 폴더와 산출 폴더(저장소 뿌리 기준) |

| `entries[].role` | `reference`(기준 시트: 정렬을 계산), `layer`(부품: `ref`의 변환을 그대로 물려받는다), `derived`(원본 없음: `derive`가 기준 화소에서 골라 만든다, 아래 「파생 레이어」), `strip`(띠: 아래 「띠 정규화」) |
| `grid` · `cell` · `rows` | 원본 격자 [열, 행], 논리 칸 [폭, 높이], 행별 `{action, frames}`. `frames` 밖의 칸은 빈 칸이다 |
| `palette` | 매니페스트 `palette_sets` 키, 또는 `palettes` 묶음 이름 배열(예: 캐릭터에서 효과 색 `fx`를 뺄 때) |
| `align` | `{mode:"ground", bottom, center_x}`(ASSET_ORDERS 0.4·0.5절) 또는 `{mode:"center"}`(기준점이 따로 붙는 무기·소품) |
| `scale` | 원본 화소 몇 개가 논리 화소 1개인가. 적지 않으면 `max(원본 칸 폭/논리 칸 폭, 원본 칸 높이/논리 칸 높이)` |
| `scale_to_spec` | `{rows:[행 번호 또는 동작 이름], height:<논리 키>}`. `scale` 대신 시트 축척을 규격 키에 맞춘다(아래 「시트 축척 맞춤」). `scale`과 함께 못 쓴다 |
| `preview` | 창 모형의 캐릭터·적·소품, 정합 확인 레이어, 32/48 비교 쌍, 들판 배경 층 |

### 띠 정규화 (`role: "strip"`)

장면 4칸(512×64)·배경 층(256×64) 같은 띠는 격자가 아니라 **내용에서 띠를 찾아** 잘라 낸다. 캔버스 크기·띠 위치는 상관없다.
**늘리지 않고 잘라서** 규격 비율에 맞춘다(2026-09-25 결정: 비율이 다른 띠를 늘리면 그림이 비틀린다).

```json
{ "name": "es18_parent_letter_48", "source": "es18-parent-letter-48.png", "role": "strip", "size": [512, 64], "cols": 4, "fit": "crop", "palette": null },
{ "name": "bg_h1_river_meadow_summer_day", "source": "w10-h1-river-meadow-summer-day-r3.png", "role": "strip", "size": [256, 64], "fit": "crop", "tile": true, "palette": null }
```
(`docs/art/imagegen.v05.map.json`에 들어 있다.)

| 키 | 뜻 |
| --- | --- |
| `size` | 논리 크기 [가로, 세로]. 산출 PNG 크기 |
| `cols` | 검수 확대본에 칸 경계를 그을 칸 수(장면 4). 기본 1. `size[0]`을 나눠야 한다 |
| `fill` | `opaque`(기본, 띠 전체가 그림) · `partial`(하늘 자리가 비는 층: 가로 범위와 바닥으로 띠를 잡고 높이 = 가로 / `size` 비율) |
| `fit` | `crop`(기본) = 잘라서 비율 맞춤 · `stretch` = 옛 방식(찾은 띠 전체를 가로·세로 다른 배율로 뽑아 비틀린다) |
| `tile` | 이어 붙는 배경 층이라 넓으면 가로로 잘라도 된다. 기본 `false`(장면: 가로로 자르면 칸이 잘려 거절) |
| `palette` | 팔레트 키·묶음 목록이면 평균 색을 가장 가까운 팔레트 색으로 스냅. **`null`이면 색을 그대로 둔다** — 배경 품질 기준(D71)의 풍부한 배경을 포스터화하지 않으려고 배경은 `null`을 쓴다 |

1. **띠 찾기**(`strip.ts findBand`, 납품 문과 같은 함수): 그림 화소가 우세한 행(그 행 그림 화소가 최다 행의 절반 이상) 첫~끝 행, 그 안에서 그림 화소가 절반 이상인 첫~끝 열.
   **비율 맞춤**(`fitBand`, `fit: "crop"`): 바닥 행(지면선 쪽)은 언제나 남긴다.
   - 높다(장면 6:1 vs 8:1 등) → **위(천장·하늘)를 잘라 낸다**. partial 층은 그림이 우세한 행이 가로 / 비율보다 높을 때 위를 자른다.
   - 넓다 + `tile` → 규격 폭의 창 가운데 **이음 점수**(창 왼쪽 4열과 오른쪽 4열의 화소별 redmean 거리 평균, 한쪽만 그림이면 765; 0 = 같다)가 가장 작은 창으로 가로를 자른다.
   - 넓다 + `tile` 아님(장면) → 2% 이하면 그만큼 눌러 뽑고, 넘으면 **거절**한다(칸을 잘라야 한다).
2. **면적 평균(상자) 재표본**: 띠를 `size`로 나눈 원본 칸(분수 경계는 겹친 면적으로 가중)에서 그림 화소가 절반 이상이면 불투명, 색은 그림 화소의 면적 가중 평균. 알파는 0·255 두 값.
3. 팔레트가 있으면 스냅. 색이 255개 이하면 인덱스 PNG, 넘으면(`palette: null` 배경) **RGBA PNG**로 쓴다.
4. 보고 JSON: 찾은 띠 `band_found`, 뽑은 띠 `band` `[x, y, w, h]`, `crop_top`, `crop_x` [왼쪽, 오른쪽], `seam`, 비율(뽑은 띠·규격), 축척 [가로, 세로],
   `anisotropy`(가로 축척 / 세로 축척, crop이면 1), 뽑은 띠 밖 버린 화소(자른 행·열 포함), 불투명·투명 수, 색 수, `notes`.
   v05 결과: es18 1536×255 → 위 63행 자름, 축척 3/3 · w10 1983×393 → 좌 228·우 183열 자름(이음 149.5), 축척 6.14/6.14.
5. `preview`는 띠를 체크무늬 위 ×4(칸 경계 표시)로 그리고, `preview.field`에 띠 이름을 두면 창 모형 배경으로 깐다.

### 처리 순서 (칸마다)

1. **배경 열쇠**: 알파 < `alpha_threshold`, 열쇠 색 근처, 자홍 번짐이면 배경.
2. **칸 배정**: 전경 화소를 8방향 덩어리로 묶어 **무게중심이 든 격자 칸**에 준다. 생성 그림은 발끝·칼끝이 격자선을 몇 화소 넘기 때문에, 격자선으로 자르면 발이 잘리고 이웃 칸에 조각이 생긴다.
3. **팔레트 번호**: 원본 화소마다 가장 가까운 팔레트 색(가중 RGB 거리 redmean).
4. **블록 다수결**: 블록 = 원본 `scale`×`scale` 화소. 불투명 화소가 절반 이상이면 불투명, 색은 최다 팔레트 번호. 블록 격자의 위상은 색 경계가 블록 경계에 가장 많이 걸리는 값.
5. **외톨이 화소 제거**(8방향으로 이웃 없는 1화소).
6. **정렬**: 기준 시트만 계산한다. `ground`는 가장 아래 불투명 행을 `bottom`에, 불투명 화소 x의 중앙값(칼·꼬리에 덜 끌리는 몸 중심)을 `center_x`에 둔다. **레이어는 기준 시트의 축척·블록 기준점·이동을 그대로 쓴다** — 따로 정렬하면 칸마다 어긋난다.
7. 칸 밖으로 나간 화소는 버리고 센다. 빈 칸이어야 할 곳의 내용도 버리고 보고한다.

**시트 축척 맞춤(`scale_to_spec`)**: 생성기는 인물을 규격 키보다 크게·작게 그리곤 한다(v05 걷기: 틀 S 5에서 46~47블록, 규격 40).
시트 하나에 축척 하나를 찾아 기준 행(예: 선 자세 행) 프레임 키의 중앙값이 `height`(D74: 선 키 40, 앉은 키 35 …)가 되게 한다.
첫 추정 = 기준 행 원본 키(소유 화소 bbox 높이) 중앙값 / `height`, 그 둘레 ±3%(0.25% 간격)를 가까운 순서로 정규화해 정규화 키 중앙값이
정확히 `height`인 첫 축척을 쓴다(블록 다수결·위상으로 키가 ±1 흔들린다). 다른 행·레이어는 같은 축척을 쓰고, 칸마다 지면선·중심 정렬은 위 6단계 그대로다.
**이것은 생성 화소를 형식(논리 격자)에 맞게 다시 뽑는 것일 뿐, 새로 그리거나 모양을 고치지 않는다(D66 취지)** — 그래서 문(`gate`)은 규격 키 차이를 실패가 아니라
경고(정규화가 걸 배율)로 알린다. 보고 `scale_origin`은 `spec`, `notes` 첫 줄에 원본 키·찾은 축척·배율을 적는다.

보고 JSON(`<이름>.json`)에는 시트별 칸 비율·축척·**원본 그림에서 잰 화소 블록 크기**(색 경계 주기의 푸리에 추정)와 경고, 칸별 원본 bbox·블록 기준점·이동·불투명 수·칸 밖 버림·외톨이 제거·bbox·사용 색·팔레트 오차(평균·최대)·블록 순도가 들어간다.
축척과 원본 블록 크기가 15% 넘게 다르면 경고한다(합쳐지면 가는 선이 빠지고, 늘어나면 계단이 생긴다).

### 레이어 정합 기준 (`layers`)

| 값 | 뜻 | 기본 기준 |
| --- | --- | --- |
| 포함률 | 레이어 화소 가운데 기준 실루엣 안 비율 | ≥ 0.95 (`--min-containment`) |
| 최적 이동 | ±3 논리 화소 안에서 **색 일치율**이 가장 높은 이동(0.01 안쪽이면 작은 이동). 실루엣 포함률로 고르면 칼날처럼 가는 레이어가 날 방향으로 미끄러져도 1.0이라 쓸 수 없다 | 체비쇼프 ≤ 1 (`--max-shift`) |
| 피부 겹침 | 옷 레이어(`--clothing` 또는 대응표 `clothing: true`) 화소 가운데 기준 시트의 같은 자리가 피부색인 비율 | ≤ 0.03 (`--max-skin`) |

피부색은 매니페스트 `skin` 묶음에서 **옷 레이어가 쓰는 피부 아닌 색과 가중 거리 40 미만인 색을 뺀 것**이고, 상하좌우 이웃 2개 이상이 피부색인 화소만 센다.
원본의 크림색 옷이 `#F0E6CC`와 `#F6D9C2` 사이라 기준 시트에서 옷이 두 색으로 갈라지고, 옷 음영 일부가 피부 중간색으로 스냅되기 때문이다.

### 알려진 한계

- **색 수**: 원본 화소마다 스냅하므로 면 안에 두 팔레트 색이 섞여 점무늬가 남고, 칸당 색 수가 카드 상한(몸체+얼굴 6, 적 12)을 크게 넘는다. 색 줄이기(묶음별 대표색 고정)는 아직 없다 — `check`의 M4를 통과하지 못한다.
- **무기 기준점**: `hand_f`·`back` 기준점(.anchors.json)이 없어 무기 시트는 가운데 정렬만 한다. 몸체와 1:1로 대응하는 무기 시트는 기준 시트의 레이어로 뽑아야 한다(검 레이어처럼).
- **시트 배치**: 출력은 원본 격자 배치 그대로다(예 동작 18칸 6×4). 15 §12.2의 10행 몸체 시트·3행 무기 시트로 옮기는 것은 다음 단계다.
- 원본 화소 블록 추정은 생성 그림의 격자가 고르지 않아 ±10% 정도다. 면이 넓은 레이어에서는 흔들려 레이어는 재지 않는다.

## 파생 레이어 (`derive`)

생성기는 합성 기준 시트와, 그것을 편집한 몸체·머리카락 레이어는 잘 만들지만(정합 통과) 옷·무기 레이어는 두 번 연달아
실패했다(소매를 피부 위에 다시 그림 5~16%, 1~3px 밀림, 칼을 다시 그림). 결정(2026-09-24): **옷·무기 레이어는 우리 도구가
기준 시트의 생성 화소에서 골라 낸다.** 화소를 고르고 자르는 것은 되고, 새 화소를 그리는 것은 안 된다.

```bash
pnpm exec tsx tools/art-check/src/cli.ts normalize                       # 미리보기가 읽는 기준·빼는 레이어 PNG(derive 자체는 메모리에서 정규화한다)
pnpm exec tsx tools/art-check/src/cli.ts derive                          # docs/art/imagegen.map.json의 derived 항목
pnpm exec tsx tools/art-check/src/cli.ts derive docs/art/imagegen.v04.map.json --name derived_d_48
pnpm exec tsx tools/art-check/src/cli.ts preview                         # derived-<이름>.x4.png 포함
```

산출: `out_dir/<파생>_<부류>.png`(부류마다 기준 시트와 같은 크기의 인덱스 PNG)와 `out_dir/<파생>.json`(칸별 보고).
색 출처 `reference`면 빼는 레이어마다 `out_dir/<파생>_<레이어>.png`(모양은 생성 레이어, 보이는 화소의 색은 기준)도 쓴다.
재합성이 한 칸이라도 `min_recompose` 미만이면 종료 코드 1(`--min-recompose`로 덮어쓴다).

### 대응표 항목 `role: "derived"`

```json
{
  "name": "derived_actions18_48", "role": "derived", "ref": "ref_actions18_48", "color_source": "reference",
  "subtract": ["body_actions18_48", "hair_actions18_48", "sword_actions18_48"],
  "order": ["body_actions18_48", "cloth", "hair_actions18_48", "sword_actions18_48"],
  "match_distance": 100, "reach": 3, "min_core": 3, "min_recompose": 0.98,
  "classes": [
    { "name": "cloth", "core": ["#F0E6CC"], "extra": ["leather", "bronze", "outline", "#2F2420"], "loose": ["leather", "bronze"], "place": "inside" }
  ]
}
```

| 키 | 뜻 |
| --- | --- |
| `subtract` | 빼는 레이어(같은 기준 시트의 `layer` 항목): 몸체·머리카락·얼굴·합격한 추출 무기 |
| `color_source` | `layer`(기본) = 빼는 레이어를 생성기 색 그대로 쌓는다(아래 「규칙」) · `reference` = 모양은 생성 레이어, 색은 기준(아래 「색 출처 reference」) |
| `order` | 그리기 순서(뒤 → 앞, 15 §3.1: 몸체 → 얼굴 → 방어구 몸통(옷) → 머리카락 → 앞 부품(무기)). `subtract`와 부류 이름을 모두 한 번씩 |
| `match_distance` | 기준 화소가 맨 위 빼는 레이어 화소와 가중 거리(redmean) 이 값 이하면 「설명된 화소」. 재합성 비교도 같은 값. 기본 100 |
| `classes[].core` | 씨앗 색(팔레트 묶음 이름 또는 `#RRGGBB`). 부류끼리 겹치면 안 된다 |
| `classes[].extra` | 씨앗에 붙기만 하는 색(부류끼리 겹쳐도 된다). 어두운 윤곽은 `#2F2420`(머리카락 묶음)으로 스냅되는 일이 많아 따로 적는다 |
| `classes[].place` | `outside` = 빼는 레이어 실루엣 밖에 닿는 덩어리만(무기) · `inside` = 몸 안 떨어진 조각도(옷) |
| `classes[].loose` | `inside` 부류가 씨앗 없이 떨어진 조각을 가지려면 조각 화소 절반 이상이 `core` 또는 이 색이어야 한다(허리끈 가죽) |
| `classes[].compare` | 겹침(정밀·재현)을 보고할 비교 레이어(예: 합격한 추출 검) |
| `reach` · `min_core` | 씨앗에서 `extra`를 붙이는 걸음 수(기본 3) · core 덩어리 최소 화소(기본 3) |

### 규칙 (칸마다, 논리 화소, 기준 시트와 같은 칸별 변환)

1. **남은 화소** = 기준이 불투명한데 빼는 레이어의 맨 위 화소가 없거나 `match_distance`를 넘게 다른 자리.
   거리 0(스냅 색 완전 일치)을 쓰지 않는 까닭: 생성기가 떼어 낸 몸체·머리카락은 모양은 맞지만 **음영을 다시 칠한다** —
   원본 화소 단계에서도 머리카락 레이어와 기준의 색 거리가 대부분 40~90이고, 스냅 뒤 같은 색은 26~39%뿐이다.
2. **씨앗**: 남은 화소 가운데 `core` 색 8방향 덩어리(`min_core` 이상).
3. **붙이기**: 씨앗에서 남은 화소를 따라 `reach` 걸음까지 그 부류의 `core`·`extra` 색만. 같은 걸음에 두 부류가 닿으면 이웃이 많은 쪽, 같으면 목록 앞 부류(`ambiguous`로 센다).
4. **outside 부류**: 덩어리에 실루엣 밖 화소가 하나도 없으면 버린다(바지 위 금속색 음영 등).
5. **inside 부류**: 씨앗에 닿지 않은 남은 화소 덩어리(부류 색이 아닌 남은 화소까지 이어 잰다)가 실루엣 밖에 닿지 않고 절반 이상이 `core`·`loose` 색이면 가진다.
   덩어리를 남은 화소 전체로 재는 까닭: 몸체만 빼는 v04에서 머리카락 속 가죽색 조각이 따로 떨어져 옷으로 가는 것을 막는다.
6. **가려짐**: 그리기 순서에서 부류보다 위인 빼는 레이어가 불투명한 자리는 그 부류가 가질 수 없다(옷은 머리카락 아래).
7. 나머지 = **잔여**, 이유별로 센다: `no_class`(부류 색 아님 — 피부·머리카락 음영, 얼굴), `blocked`(가려짐), `unreached`(부류 색이지만 씨앗·조각 규칙 밖), `rejected`(4번·min_core).
   `residual_offset`은 잔여 가운데 1화소 옆에 같은 색 레이어 화소가 있는 것(레이어 1px 어긋남)이다(겹쳐 센다).

부류 화소는 기준 시트의 스냅 색 그대로 복사한다. 부류의 색은 팔레트 묶음으로만 가리므로 **옷 레이어에 피부 묶음 색은 들어가지 않는다**
(피부 밝은색 `#F6D9C2`와 옷 크림 `#F0E6CC`처럼 거리 31인 색은 스냅 단계에서 뒤바뀔 수 있다).

### 색 출처 reference (모양은 생성 레이어, 색은 기준)

생성기가 떼어 낸 몸체·머리카락은 **모양은 맞지만(정합 통과) 색을 다시 칠한다**(스냅 뒤 같은 색 26~39%, v03 머리카락은 밝은 주황 쪽으로 거리 79~125).
그래서 레이어의 모양(불투명 가림막)만 쓰고, 기준에서 보이는 화소의 색은 기준 시트에서 가져온다. 새 화소는 그리지 않는다(D66) —
보이는 화소는 기준의 생성 화소, 가려진 화소는 생성 레이어의 생성 화소다. 칸마다, 논리 화소로:

1. **보이는 화소 배정**: 기준 불투명 화소는 그 자리를 덮는 **그리기 순서 맨 위** 빼는 레이어의 것이다(15 §3.1: 몸체 < 얼굴 < 옷 < 머리카락 < 앞 부품).
   「같은 재질」 = 레이어 화소와 기준 화소가 가중 거리 ≤ `match_distance` 또는 **같은 팔레트 묶음**(다시 칠한 음영).
   - 맨 위가 같은 재질이 아니고 더 아래 레이어가 같은 재질이면 아래 레이어의 것(칼자루를 쥔 손, 머리카락 앞으로 올린 팔). 단 그런 화소의 8방향 덩어리가
     `min_core` 이상일 때만 — 흩어진 점은 다시 칠한 머리카락 음영이 몸체의 어두운 피부 음영과 가까워서 생기고, 내려주면 머리카락에 구멍이 난다.
   - **피부 위 소매**: 맨 위 레이어보다 위에 그리는 부류가 있고(몸체 위 옷) 같은 재질이 아니면 남은 화소 → 부류 나누기(위 「규칙」 2~6).
     같은 재질이면 레이어에 둔다(크림 속옷 = 크림 겉옷 몸판, 눈으로 구별되지 않는다).
   - 위에 그리는 부류가 없으면(머리카락 아래의 옷은 보일 수 없다) 색이 멀어도 맨 위 레이어의 것이다.
2. **부류가 갖지 않은 남은 화소**: 어느 레이어도 덮지 않은 자리(실루엣 가장자리 1px 어긋남)는 이웃한 레이어 화소와 기준 색이 가까우면
   그 레이어로 넓힌다(`reach` 걸음, `grown`). 레이어가 덮은 자리는 맨 위 레이어가 **흡수**한다(`absorbed` — 눈·허리끈·빵 등 분류 못 한 화소).
   덮인 자리를 더 위 레이어로 넓히지 않는 까닭: 눈(어두운 색)이 앞머리를 따라 머리카락으로 간다. 둘 다 아니면 **빠짐**(`missing`).
3. **산출 레이어**: 배정된 화소 = 기준 색. **가려진** 화소(기준에서 더 위 레이어·부류 아래) = 생성기 자기 색 그대로(장비를 바꿀 때 드러나는 자리).
   기준에서 이 레이어보다 아래 것이 보이는 자리는 버린다(`trimmed`, 삐져나옴). 기준 실루엣 밖 화소도 버린다(`dropped`).
4. 부류 레이어는 전과 같이 기준 색.

이렇게 하면 재합성은 기준에서 보이는 화소마다 기준 색이 되므로 **구성상 거의 100%**다(어긋나는 것은 `missing`뿐). 그래서 재합성 비율보다
보고의 `totals.layers`(레이어별 `visible`·`recolored`·`mean_shift`·`grown`·`absorbed`·`hidden`·`trimmed`·`dropped`)와 `totals.missing`이 뜻있는 값이다.
`absorbed` + `missing`이 「분류 못 한 남은 화소」다. 재합성 검사는 그대로 둔다(빠짐을 잡는다).

### 재합성 검사 (oracle)

빼는 레이어와 부류 레이어를 `order`대로 쌓아 기준 시트와 내용 칸마다 비교한다. 분모 = 둘 중 하나라도 불투명한 화소,
맞음 = 둘 다 불투명이고 거리 ≤ `match_distance`. 칸마다 `rate ≥ min_recompose`(기본 0.98)여야 한다.
보고에는 참고로 스냅 색 완전 일치율(`exact_rate`)과 빠짐(기준에만)·넘침(재합성에만)·색 어긋남 수를 같이 적는다.

미리보기 `derived-<이름>.x4.png`: 칸마다 [기준 | 재합성 | 파생 부류만 | 차이]. 차이 색은 회색 = 같음, 주황 = 색이 허용 거리를 넘게 다름,
파랑 = 빠짐, 빨강 = 넘침.

### 알려진 한계 (파생)

- **옷 벗긴 모습(교체 시험)**: 색 출처 `reference`의 다섯째 칸(몸체 + 머리카락 + 검, 옷 없이)은 맨몸이 아니라 **구멍 난 겉옷**이다.
  크림 속옷 = 크림 겉옷이라 겉옷 몸판·허리끈·주름이 몸체에 남고, 옷 부류가 가져간 조각(목깃·소매·밑단 일부) 자리에만 생성기 몸체의 피부·민소매가 드러난다.
  드러난 자리는 생성기 음영, 둘레는 기준 음영이라 얼룩져 보인다. 겉옷을 다른 장비로 갈아입히려면 생성기의 **겉옷만 편집본을 모양 가림막으로** 받아
  머리카락처럼 쓰는 것이 다음 후보다(예전 옷 추출 불합격 사유 중 「다시 그림」은 색을 기준에서 가져오므로 문제가 줄고, 「1~3px 밀림」은 남는다).
- **그리기 순서와 어긋난 자세**: 동작 (1,1)은 팔을 머리카락 앞으로 올린다. 그 자리는 몸체로 내려주고 머리카락에서는 버리므로(`trimmed`)
  머리카락 레이어에 팔 모양 구멍이 난다. 이 몸체와 겹치면 맞지만, 팔을 내린 다른 몸체와 쓰면 구멍이 보인다(가려진 화소로 남기면 이번에는 팔을 덮는다).

- **속옷과 겉옷이 같은 색**: 몸체의 크림 속옷(`#F0E6CC`)과 겉옷 몸판이 같은 색이라, 몸통 위 겉옷 화소는 「설명된 화소」가 되어 옷 레이어에 없다.
  재합성은 그 자리를 몸체 속옷으로 그리므로 맞다고 나온다. 옷 레이어는 소매·밑단·허리끈·기운 자국처럼 **속옷과 다른 부분만** 담는다.
  v04 E(환호·쓰러짐)는 겉옷이 속옷과 거의 같아 옷 레이어가 12화소뿐이다. 겉옷을 다른 장비로 갈아입히려면 이 방식으로는 몸판을 얻을 수 없다.
- **칼날이 비슷한 색 위를 지날 때**: 금속 `#B4B2B0`과 몸체 바지 회색, 밝은 날 `#E8E6E0`과 크림 속옷(거리 약 30)은 허용 거리 안이라, 그 위를 지나는 칼날 토막은 빠진다(v03 재현 61.8%의 주원인).
- **팔레트 묶음은 의미가 아니다**: 생성 색이 팔레트 사이에 있어 머리카락 갈색이 가죽 묶음으로, 윤곽이 머리카락 묶음 `#2F2420`으로 스냅된다. 그래서 옷 `core`는 묶음 `cloth` 대신
  겉옷 크림 `#F0E6CC` 하나만 쓴다(묶음 `cloth`의 빨강 `#B04A42`는 환호의 벌린 입과 같은 색이다).
- 허용 거리를 올리면 머리카락 음영이 설명되는 대신 옷·칼이 더 빠지고, 내리면 음영 차이가 잔여로 쌓인다. 98%에 닿으려면 빼는 레이어의 색이 기준과 같아야 한다.
- 안내 레이어(불합격 추출 옷을 넓혀 위치만 쓰는 방식)도 시험했지만 v04에서 허리끈을 잃고 입을 막지 못해 넣지 않았다.
- **몸체 속옷·바지와 옷 색의 허용 거리(D73)**: 속옷(`underlayer`)·바지(`trousers`)는 A01 천옷과 가중 거리 110 이상이라 기본 `match_distance` 100에서 천옷과 갈린다.
  그러나 **속옷 그늘 `#546E7A`는 A03 청색 허리띠 `#3E5A7E`와 52, 금속 `#7D7B80`과 69, `#4C4A52`와 98, 속옷 밝음 `#7EA6B8`은 금속 `#B4B2B0`과 91**이라, 허용 거리 100에서는
  A03(가죽갑옷 + 청색 허리띠)·금속 계열 시트(A06, 청동으로 팔레트만 바꾸는 A07 포함)의 옷 화소가 몸체 속옷으로 「설명」되어 옷 레이어에서 빠진다.
  이 복장들을 파생할 때는 대응표 항목의 `match_distance`를 복장마다 낮춘다(A03 50 미만, 금속 계열 65 미만). 바지는 모든 장비·피부·머리 색과 101 이상이라 해당 없다.
  옛 속옷·바지(크림 `#F0E6CC` · 회색 `#C8C2B8` `#9A948C`)로 뗀 v03·v04 몸체 레이어는 이 결정 전 것이라, 새 색으로 다시 뗄 때까지 위 「옷 벗긴 모습」 한계가 그대로다.

## 배치 틀과 납품 문 (`template` · `gate`)

결정(2026-09-24): 생성 그림을 규격에 **빈틈없이** 맞추려고 ① 배치 틀 이미지를 생성기에 입력으로 주고, ② 프롬프트에 틀 이름과 수치
(S·칸·지면선·중심·키)를 적고, ③ 납품을 문(`gate`)에 통과시켜 떨어지면 다시 생성할 영어 지적문을 돌려준다.

```bash
pnpm art:template                         # docs/art/templates/specs.json의 모든 시트 → docs/art/templates/<이름>.{grid,placeholder,silhouette}.png + <이름>.json
pnpm art:template chr_actions_a enm_rat   # 고른 시트만
pnpm art:gate <납품.png> --spec chr_actions_a            # 합격 0 · 불합격 1 · 사용법·읽기 실패 2
pnpm art:gate <옛 납품.png> --spec chr_actions_a --no-canvas --rows idle,attack,sit_eat,sleep
pnpm art:gate <납품.png> --spec enm_rat --json            # 기계용(칸별 수치·failures·feedback)
```

### 배치 틀 규격

| 항목 | 규칙 |
| --- | --- |
| 캔버스 | 정확히 **1536×1024**(가로). 격자가 더 크게(S가 더 크게) 들어갈 때만 1024×1536(세로) |
| 배경 | 단색 `#FF00FF` 한 면 |
| 논리 화소 | 논리 화소 1개 = 이미지 **S×S** 정수 블록 |
| S | `cols·cellW·S ≤ canvasW − 64` 이고 `rows·cellH·S ≤ canvasH − 64`인 가장 큰 정수(사방 최소 32화소 여백). 캐릭터 48×48 칸 6열 × 5행 → S 4(칸 192화소), 들쥐 32×24 4×5 → S 8 |
| 격자 위치 | 캔버스 가운데. 칸 (c, r) 원점 = (x0 + c·cellW·S, y0 + r·cellH·S). `x0 = ⌊(canvasW − 격자 폭)/2⌋` |
| 띠(배경·이벤트 장면) | 가로 여백 0(폭 전체): 배경 256×64 → S 6 → 1536×384, y 320..703 · 이벤트 장면 128×64 × 4프레임 = 512×64 → S 3 → 1536×192, y 416..607 |
| 안내 눈금 `#00FFFF` | **칸 밖 여백에만**. 격자에서 4화소 떨어져: 열·행 경계(길이 24, 두께 2) · 칸 가로 중심 논리 열(길이 12, 폭 S) · 지면선 논리 행(길이 12, 높이 S — 그림 최하단 화소의 **바로 아래 행**, ASSET_ORDERS 0.4) · 나는 적의 부양선(최하단 바로 아래 행, 길이 8). 가로 여백이 없는 띠는 위·아래 눈금만 |
| `grid` 판 | 자홍 캔버스 + 여백 눈금. 칸 안에는 아무것도 없다 |
| `placeholder` 판 | `grid` + 쓰는 칸마다 합격 기준 그림(정규화된 게임 규격 프레임, 예 `assets/game/ref_actions18_48.png` 대기 1)을 ×S 최근접 확대해 규격 지면선(− lift)·가로 중심(열 중앙값)에 놓은 것. 크기·위치 기준이고 생성기가 그 자리를 새로 그린다 |
| `silhouette` 판 | `placeholder`의 그림을 단색 `#808080`으로 칠한 것 |

틀 두 가지(`grid` · `placeholder`/`silhouette`) 가운데 생성기가 무엇을 더 잘 따르는지는 다음 아트 라운드에서 가린다.
자리표시 원본(`assets/game/…`)은 생성 산출물이라 `art:template` 전에 `art:normalize`(v04 늑대·기준 D는 대응표 `docs/art/imagegen.v04.map.json`)를 돌려야 한다.
원본이 없는 계열(박쥐·코볼트·보스·효과·소품·초상·아이콘·배경·장면)은 `grid` 판만 만든다.

### 문 검사 (`gate`)

그림 화소 = 배경 열쇠(알파 < 128 · `#FF00FF` 거리 90 이하 · 자홍 번짐)도 안내 색(`#00FFFF` 거리 80 이하)도 아닌 화소.
8방향 덩어리의 무게중심이 든 칸이 주인이다(S²/2 화소 미만 덩어리는 티로 센다). 띠(`fill`)는 칸 좌표로 나눈다.

**띠(`fill` ≠ null: `scene_event` · `bg_far` · `bg_mid` · `bg_near`)는 틀 위치가 아니라 내용에서 띠를 찾는다**(정규화 띠 항목 `fit: "crop"`과 같은 `findBand`·`fitBand`).
위 「띠 정규화」의 규칙대로 잘라서 비율을 맞춘 띠를 규격 열 수로 등분해 칸을 정하고 S = 띠 가로 / 논리 가로
(표 머리 `S … (band)`, `띠 x y w×h 비율 · 위 자름 · 좌우 자름 · 이음`). 배경 계열 `bg`는 `specs.json`에서 `"tile": true`다.
캔버스 크기·틀 띠 위치 차이·자르기는 경고(`canvas` · `band` · `crop`)다. 실패는 띠 없음(`band`) · 장면 띠가 규격보다 넓음(`aspect`) ·
찾은 띠 밖 그림(`stray`, 띠 가장자리 ⌈S/2⌉ 화소 번짐과 비율 맞추느라 자른 부분은 뺀다) · 칸 채움(`fill` · `ground_band`)이다. 캔버스 모드·`--no-canvas` 모두 같다.

**원칙(2026-09-25, v05 검수)**: 정규화(`normalize`, 필요하면 `scale_to_spec`)가 **고칠 수 없는 것만 실패**(종료 1, 지적문에 들어간다).
정규화가 고치는 것은 **경고**(종료 0, `Warnings` 아래 찍고 지적문에는 넣지 않는다 — 우리가 고칠 것을 생성기에 다시 시키지 않는다).
단위는 모두 **논리 화소** = 이미지 화소 / S. 캔버스 모드 S = 틀 S, `--no-canvas` S = 칸 화소 / 칸 논리 크기(정규화 `cell_ratio`와 같은 값).
그린 화소 블록 크기는 S가 아니다(v05: 틀 S 5에 생성기 블록 4.1~4.6).

**칸 배정**: 먼저 무게중심이 든 틀 칸(`--no-canvas`는 등간격 칸). 쓰는 칸·빈 칸이 규격과 안 맞으면 **내용에서 격자를 추정**한다 —
큰 덩어리(쓰는 칸 수 N번째로 큰 것의 25% 이상)가 정확히 N개이고, 무게중심 y 간격이 그림 키 중앙값의 절반을 넘는 곳에서 나눈 행 수·행별 수가
규격과 같고, 행 안 x 순서가 추정 열 간격으로 왼쪽부터 빈틈없이 놓였을 때만 그 배정을 쓴다(표 머리 `칸 내용 추정`). 작은 조각은 가장 가까운 그림에 붙는다.

  남은 것: 늑대 `attack 2` 자리표시는 대기 1을 lift 3만큼 올려 놓아 위 여백을 2블록 넘는다(자리표시만의 일, 실제 도약 칸은 몸을 낮춘다). 합격 그림에서 몸이 가장 긴 공격 칸(들쥐 29, 늑대 45 논리 화소)은 가운데 두어도 여백 2를 1 넘는다.

## 규격을 고치려면

규격은 코드에 없다. 전부 `docs/art/assets.manifest.json`에 있다. 새 산출물은 `assets` 배열에 항목을 더하고,
값이 아직 정해지지 않은 산출물은 `unspecified`에 적는다(검사기가 「명세 미정」으로 같이 보고한다).
매니페스트 자체의 앞뒤(크기 = 칸 × 격자, 행 프레임 합 = frames, 팔레트 키 존재, 경로 중복)는 읽는 즉시 검증하며,
틀리면 검사 전에 종료 코드 2로 멈춘다.

## 시험

```bash
node --import tsx --test "tools/art-check/test/**/*.test.ts"
```

시험은 합성 PNG를 코드로 만들어(`test/helpers/png-encode.ts`) 항목마다 통과·실패 사례를 함께 본다.
정규화 시험(`test/normalize.test.ts`)은 논리 그림을 잡음과 함께 정수배로 키운 자홍 배경 원본을 코드로 만들어
배경 열쇠·다수결 축소·정렬·격자선 넘김·레이어 변환 물려받기·팔레트 스냅·PNG 기록 왕복·정합 측정을 본다.
틀·문 시험(`test/template.test.ts`)은 작은 시험 규격(캔버스 256×192)으로 S·세로 캔버스·띠 배치, 눈금이 칸 밖에만 있는지, 자리표시의
지면선(− lift)·중심, 틀대로 그린 합성 납품의 통과와 지면선·점프·중심·키·빈 칸·없는 칸·안내 색·격자 밖·반투명·블록·캔버스·띠 채움 실패,
`--no-canvas`의 행별 지면선 비교, 명령줄 종료 코드를 본다.
